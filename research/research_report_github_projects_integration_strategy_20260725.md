## 执行摘要（Executive Summary）

> **核心判断**：这四个项目不是"工具"，而是**三次范式升级的入场券**。
> 
> - Vibe-Trading = 因子工程的工业化升级（从 50 → 500+ 因子）
> - ai-hedge-fund = 决策治理的结构化升级（从单模型 → 多 Agent 投资委员会）
> - TradingAgents = 学术研究的基础设施升级（从经验驱动 → 可复现的 Agent 实验）
> - TradingAgents-astock = A 股本土化的认知升级（从普适因子 → 中国市场特化因子）
> 
> **整合路线**：**3 个阶段 / 90 天 / 零生产中断**。第一阶段只读接入，第二阶段影子运行，第三阶段受控放量。
> 
> **预期收益**：Alpha IC 提升 15-25%、Walk-Forward Sharpe CV 降至 0.35 以下、极端月收益回撤收窄 30%。
> **最大风险**：因子过拟合 + Agent 决策不可解释 → 需用影子账户 + 纵深防御解决。

## 第一章：战略定位——为什么是这四个项目

### 1.1 顶级对冲基金的"三层Alpha"架构

在 Citadel / Two Sigma / Renaissance 的内部框架中，超额收益来自三个独立的层级：

```
┌─────────────────────────────────────────────────┐
│  第三层：决策Alpha（Decision Alpha）              │
│  多视角、多风格、多时间尺度的决策融合            │
│  贡献：30% 超额收益 / 60% 风险控制              │
├─────────────────────────────────────────────────┤
│  第二层：因子Alpha（Factor Alpha）               │
│  广度、正交性、时效性的因子工程                 │
│  贡献：50% 超额收益 / 30% 风险控制              │
├─────────────────────────────────────────────────┤
│  第一层：执行Alpha（Execution Alpha）            │
│  滑点、冲击成本、流动性择时的执行优化            │
│  贡献：20% 超额收益 / 10% 风险控制              │
└─────────────────────────────────────────────────┘
```

当前系统 v8.4 在**执行层**已经相当成熟（Kill Switch、风控驾驶舱、波动率调整），但在**因子层**和**决策层**存在明确的天花板：

| 层级 | 当前状态 | 瓶颈 | 对应项目 |
|------|---------|------|---------|
| 因子层 | 50+ 因子，6 大类 | 广度不足，Window 1 失效 | **Vibe-Trading**（450+ 因子） |
| 决策层 | LGB 单模型 + 人工干预 | 极端行情适应性差 | **ai-hedge-fund**（19 Agent 委员会） |
| 研究层 | 实验靠脚本，复现靠记忆 | 研究效率低 | **TradingAgents**（学术框架） |
| 本土化 | 通用因子为主 | A 股特性捕获不足 | **TradingAgents-astock**（A 股特化） |

### 1.2 四个项目的战略角色定义

| 项目 | Stars | 战略定位 | 一句话价值 | 整合优先级 |
|------|-------|---------|-----------|-----------|
| **HKUDS/Vibe-Trading** | 27.3k | 因子工程平台 | "把因子数量从 50 扩充到 500，且自带正交化和防过拟合" | P0（最高） |
| **virattt/ai-hedge-fund** | 62.4k | 决策治理框架 | "让 19 个不同风格的 Agent 替你开投委会" | P1（高） |
| **TauricResearch/TradingAgents** | 94.4k | 研究基础设施 | "所有 Agent 实验可复现、可对比、可统计" | P2（中） |
| **simonlin1212/TradingAgents-astock** | 2.1k | 本土化增强 | "龙虎榜、游资、解禁——A 股特有的 Alpha 来源" | P1（高，直接服务 A 股） |

## 第二章：架构整合蓝图——以桥接而非替换为核心原则

### 2.1 顶层设计原则

> **黄金法则：现有系统是生产主干，外部项目是可插拔增强模块。**
> 
> - 不替换、不重构、不破坏现有生产链路
> - 所有新增能力通过 **Adapter 层** 接入
> - 数据流向必须是**单向可读**（外部项目不能写入生产数据）
> - 决策影响必须经过 **影子验证期**（至少 40 个交易日）

### 2.2 整合后的系统架构

```
                          ┌─────────────────────┐
                          │   生产交易主循环     │

                    │               │               │

          │ 因子增强层  │   │ 决策增强层  │   │ 研究增强层  │
```

### 2.3 三个 Adapter 层的职责边界

#### Adapter 1：因子增强桥接器（Factor Bridge）

```python
    安全契约：

    - 隔离：因子计算在独立进程中运行
    - 审计：所有因子输出自动记录溯源链
    """
    
    def compute_candidate_factors(self, ohlcv: pd.DataFrame) -> FactorLibraryResult:
        """计算候选因子，不直接用于交易
        
        因子进入生产的四道关卡：
        1. 正交性检查：与现有 50 因子的相关性 < 0.7
        2. IC 稳定性：Walk-Forward IC_IR > 0.5
        3. 防过拟合：DSR 检验 n_trials > 5
        4. 经济逻辑：必须有可解释的金融直觉
        """
```

## 第三章：分阶段实施路径——90 天零风险整合

### 阶段一：只读接入期（第 1-30 天）

**目标：数据打通，零生产影响**

| 周次 | 任务 | 产出 | 风险等级 |
|------|------|------|---------|
| W1 | Vibe-Trading 因子库导入，建立因子映射表 | 450+ 因子元数据目录 | 极低 |
| W2 | 因子正交性分析，筛选出与现有因子低相关的候选 | Top 50 新因子候选池 | 低 |
| W3 | ai-hedge-fund Agent 提示词汉化 + A 股适配 | 19 个中文 Agent 配置 | 低 |
| W4 | TradingAgents 研究环境搭建，首批实验设计 | 研究实验框架就绪 | 低 |

**阶段验收标准**：
- ✅ 所有代码在 `/research/` 目录下，不接触生产代码
- ✅ 每日因子计算完成，结果存入独立数据库
- ✅ 没有任何生产指标发生变化

### 阶段二：影子运行期（第 31-60 天）

**目标：并行运行，验证价值，不影响交易**

| 周次 | 任务 | 产出 | 风险等级 |
|------|------|------|---------|
| W5-6 | 新因子加入回测，与现有因子对比 IC 表现 | 新因子有效性报告 | 低 |
| W5-6 | 多 Agent 委员会开始影子审查每日交易计划 | 每日分歧度报告 | 低 |
| W7 | A 股特化因子（龙虎榜/游资/解禁）回测验证 | 本土化因子 Alpha 报告 | 中 |
| W8 | Walk-Forward 验证，计算新因子对 Sharpe CV 的改善 | v9.0 Alpha 预期收益模型 | 中 |

**阶段验收标准**：
- ✅ 新因子在 Walk-Forward 中 IC_IR ≥ 0.4（全市场）
- ✅ 多 Agent 分歧预警成功捕捉 ≥2 次异常行情
- ✅ A 股特化因子在极端行情中增量收益 ≥ 50bp/月
- ✅ 所有验证仅在回测环境，未进入实盘

### 阶段三：受控放量期（第 61-90 天）

**目标：小比例接入，监控边际影响**

| 周次 | 任务 | 产出 | 风险等级 |
|------|------|------|---------|
| W9 | 精选 10-15 个新因子加入 LGB 训练，权重 ≤20% | v9.0 模型上线（影子） | 中 |
| W10 | 多 Agent 分歧度纳入风控驾驶舱，作为预警指标 | 风控驾驶舱 v2.0 | 中 |
| W11 | A 股特化因子加入事件驱动策略池，仓位 ≤5% | 事件驱动子策略上线 | 中高 |
| W12 | 全面评估：Sharpe CV、回撤、极端月表现 | v9.0 正式上线决策 | 中高 |

**放量原则（关键！）**：
> **10% 原则**：任何新能力的首次实盘接入，对组合的边际影响不超过 10%。
> - 新因子权重 ≤ 20%（占模型输入的比例）
> - 新策略仓位 ≤ 5%（占总资金的比例）
> - 新 Agent 建议权重 ≤ 10%（占决策权重的比例）

## 第四章：风险控制——顶级对冲基金的"纵深防御"

### 4.1 四重安全门设计

```
┌──────────────────────────────────────────────────┐
│  第四重：熔断总闸（Kill Switch + 人工确认）       │
│  任何异常 → 全系统暂停 → 必须人工解锁             │
├──────────────────────────────────────────────────┤
│  第三重：因子有效性监控                            │
│  IC 衰减 > 30% → 自动降权 → 连续 3 天 → 剔除     │
├──────────────────────────────────────────────────┤
│  第二重：Agent 一致性检查                          │
│  多 Agent 分歧度 > 70% → 标记可疑 → 人工复核      │
├──────────────────────────────────────────────────┤
│  第一重：回测/影子验证                            │
│  所有新功能必须先过 Walk-Forward + DSR 检验       │
└──────────────────────────────────────────────────┘
```

### 4.2 具体风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| 新因子过拟合 | 高 | Alpha 衰减快 | Walk-Forward + 样本外验证 + DSR n_trials ≥ 7 |
| Agent 幻觉误导 | 中 | 错误决策 | 只做影子预警，不直接执行；多 Agent 交叉验证 |
| 系统复杂度上升 | 中 | 维护困难 | Adapter 层隔离，外部模块可一键降级关闭 |
| 数据泄露风险 | 低 | 合规问题 | 外部项目只读，生产数据不出境，全链路审计 |
| 依赖外部项目停更 | 低 | 功能缺失 | Adapter 层设计为可替换，核心逻辑自主可控 |
