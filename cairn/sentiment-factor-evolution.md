# 情绪因子演化：v4.0 → v4.3

本专题记录 A 股量化系统情绪因子从 v4.0 到 v4.3 四个阶段的完整演化路径、关键决策及其经济直觉。该因子是 LightGBM 增强训练器的第 7 信号源，新闻源为东方财富个股新闻 + 新浪财经。

## 阶段概要

情绪因子经历「从保护到信任」的三阶段演进 —— v4.0 建立分级情感词典基线、v4.1 与 OHLCV 回看周期对齐、v4.2 原生处理缺失值并引入全市场聚合指数、v4.3 移除保护机制让情绪因子正常参与特征选择。

---

## v4.0 — 分级加权情感词典（基线版本）

**时间**：约 2026-07-20 前后（系统 v8.5 / v8.6 系列初期）  
**目标**：用分级权重词典替代简单的平权关键词计数，解决「多个弱信号词堆砌出虚高得分」的问题

### 核心设计

三级权重词典，按信号强度分级：

| 级别 | 权重 | 典型词条 |
|------|------|---------|
| 强信号 (strong) | 1.0 | 回购、涨停、退市、暴雷、资金链断裂、业绩预增 |
| 中信号 (medium) | 0.6 | 增持、突破、亏损、处罚、减持、重组 |
| 弱信号 (weak) | 0.3 | 提升、改善、承压、回落、调整 |

### 三项关键技术决策

1. **多词短语优先匹配**：`"创历史新高"` 优先于单独的 `"新高"`，避免重复计分和信号污染
2. **对数衰减防堆砌**：`net = (weighted_pos - weighted_neg) / log2(1 + matched_count)` —— 关键词数量的边际贡献递减，防止长篇软文/通稿获得虚高得分
3. **信号强度四级标记**：每篇文章输出 strong/medium/weak/none 标记，供下游 Agent 做分级响应（如 strong negative 触发 SentimentAgent veto）

**关键函数**：`_score_article_weighted()`（`lgb_trainer/news_sentiment.py`）

## v4.1 — 回看周期扩展（30天→250天）

**时间**：2026-07-22 前后  
**触发信号**：OHLCV 滚动特征回看 500 天，情绪因子仅 30 天导致「近期情绪变化」（如 5 日变化率）完全无统计意义

### 变更

`news_lookback_days` 从 30 改为 250，与 OHLCV 回看周期的一半对齐，确保 `market_sent_change` 等滚动衍生特征有至少 50 个有效观测点。

**决策记录**：250 天是「覆盖一个完整交易日年度 + 足够多的新闻事件日」的最小值。更长时间（500 天与 OHLCV 完全对齐）收益递减，因为新闻的情绪信号半衰期很短（通常 3-7 天）。

## v4.2 — NaN 原生处理 + 全市场聚合情绪指数

**时间**：2026-07-24 前后  
**核心问题**：A 股 ~5000 只股票中，每天有新闻覆盖的仅约 200-300 只，97% 的天数都无新闻。旧方案用前向填充 → 97% 天是合成值 → 模型识别为噪声 → 情绪因子 importance 极低。

### 决策：哨兵值替代合成填充

- 无新闻日填 **-999**（远低于正常情绪范围 [-1, 1]）
- LightGBM 将 -999 作为独立分裂节点 → 等价于「有新闻 vs 无新闻」二值分支
- `has_news` 二值特征配合使用，形成「双重编码」：has_news 回答「有没有」，raw 回答「有的话是什么方向」

> **为什么不用 0 填充？** 因为 0 在情绪空间中代表「中性情绪」，而中性是一个有意义的信号；填 0 等于误报「有新闻但中性」，混淆了信号边界。

### 新增：全市场聚合情绪指数

仅 200-300 只有新闻覆盖的股票，其情绪因子对个股选股的贡献不足以通过特征选择。解决方案是构建两个宏观情绪因子：

| 新增因子 | 计算方式 | 经济直觉 |
|---------|---------|---------|
| `market_sentiment` | 当日所有有新闻标的 `raw` 的均值 | 全市场风险偏好——正值 = 乐观、负值 = 悲观 |
| `market_sent_change` | `market_sentiment` 的 5 日差分 | 情绪拐点——上升 = 情绪改善、下降 = 恶化 |

个股维度仅保留：
- `has_news`：当日是否有该股相关新闻（0/1，关注度代理）
- `news_sentiment_raw`：新闻日分级加权情绪分（无新闻日 = -999 哨兵）

**因子总数**：4 个（2 宏观 + 2 个股），相比旧方案的纯个股方案，宏观因子提供了全场约 60%+ 覆盖率，大幅提升了情绪因子的信息密度。

## v4.3 — 移除保护机制，正常参与特征选择

**时间**：2026-08-02（今日）  
**触发信号**：v4.2 因子质量显著提升后，保护机制（强制保留）已无必要。保护机制的历史作用是「给低质量因子一个表现机会等待数据改善」，现在数据已改善到可信任水平。

### 具体变更

**旧行为**：`select_features_by_importance()` 调用时传入 `protected_patterns=["market_sent", "has_news", "news_sentiment"]`，`min_protected=1`，确保至少 1 个情绪因子强制入选 top features。

**新行为**：
- 不再传入 `protected_patterns`，情绪因子与其他因子平等参与 LightGBM feature importance 竞争
- 若所有情绪因子 importance = 0 → 自然退选，不做强制保留
- 这是「模型对因子质量的最终验证」——信息量不足的因子不应干扰模型

**配合调整**：
- `top_n_features`：20 → 30（放宽特征数上限，让情绪因子有更多竞争席位）
- `feature_selection_threshold`：3 → 1（降低入选门槛，让弱信号特征也能进入候选池）

**报告统计更新**：v4.3 报告仅统计 importance > 0 的「实际有贡献」入选；零贡献的情绪因子单独标注「未实际分裂」。

### 保护机制移除的验证逻辑

保护机制移除不等于「情绪因子被放弃」。真正的判断标准是：
- 如果 22 标的的 LightGBM 模型中，情绪因子 importance 全部为 0 → 说明情绪因子确实无效，应当从因子池移除或重新设计
- 如果部分标的中情绪因子入选且 importance > 0 → 说明在某些情境下（如小盘股、事件驱动型标的）情绪信号有独特贡献，保护机制反而掩盖了这种情境差异

### 决策边界

> 保护机制是一种「容忍低质量因子的策略」，适用场景是因子数据源正在建设中、信号质量预期会改善。当数据源质量稳定后，保护机制就变成了「允许噪声混入」的风险源。v4.3 的移除标志着情绪因子数据质量已达到「不需要特殊照顾」的水平。

## 辅助系统（独立演化路径，不与 v4.0-v4.3 版本号耦合）

### NewsSentimentEngine（`utils/news_sentiment_engine.py` v1.0）

独立于 lgb_trainer 的情感分析引擎，面向**实时信号生成**（而非因子训练）。核心能力包括多源聚合（东方财富+新浪+同花顺）、FinBERT 风格情感分类、8 类事件抽取（业绩预告/分红/增持减持/重组/处罚/诉讼/退市风险/重大合同）、供应链与同业传播、时序衰减（半衰期 24h）、异常检测。两条体系并行：`lgb_trainer/news_sentiment.py` 面向回测训练因子，`NewsSentimentEngine` 面向实时盘中信号。

### SentimentAgent（`utils/finance_agents/sentiment_agent.py`）

金融多 Agent 系统中的舆情专家（权重 13%），复用 AIReportAgent 做 LLM 情感推理，LLM 不可用时降级到规则引擎。重大负面关键词触发 `action=veto`，是风控体系的事前防线之一。

### FactorModel 集成（`utils/factor_model.py`）

五维因子模型中情绪因子作为第 6 维度（事件驱动扩展），权重 0.04，与 `event_impact` 并列最低。这反映了情绪信号的辅助定位——不替代基本面因子，而是提供短期催化剂捕捉能力。

## 后续方向

1. **数据源扩展**：当前仅东方财富个股新闻 + 股吧帖子，覆盖率不足。候选方向：同花顺 iFinD 新闻接口、雪球热帖、微博财经大 V、证监会公告自动解析
2. **情绪半衰期校准**：当前用固定 5 日变化率，不同事件类型（突发利空 vs 行业政策）的情绪衰减速度差异很大，需要按事件类型动态调参
3. **情绪拥挤度监控**：当大量标的出现同向极端情绪时（如全市场过度乐观），情绪因子可能成为反向指标而非选股信号
4. **与 Vega 监控联动**：市场恐慌情绪（极度负面 market_sentiment）通常伴随隐含波动率飙升，可开发「情绪-波动率」联合信号用于期权对冲决策
