## 一、路线图治理模式：从"历史记录堆"到 Release Control Board

### 1.1 状态漂移的机制根源
路线图同时承担"当前事实 + 历史过程"时，**每次口径修正都以"注记挂在历史段落"的方式打补丁**，旧状态永远具有误导性（本案实证：≥4 处修正注记，D11 达标日三轮修正、B2/B3 状态失实、"v8.8"口径漂移）。

**根治结构**（不是更勤快地改注记）：
```
CURRENT STATE (YAML 单一事实源)     ← 状态变更只改这里 + 决策登记表登记
RELEASE GATES (Blocker 白名单)
NEXT N DAYS                         ← 可执行节点
CURRENT QUARTER / 2027 PLAN
ARCHIVED DECISIONS (指针表)         ← 历史 = 一行决策 + 指针到 LOG/专项文档
```

**修改纪律**: 状态变更只改 YAML；修正直接改值并在决策登记表登记（不写"修正注记"）；历史过程只进 LOG；旧章节名用头部"引用兼容映射"承接存量引用（LOG append-only 不回改）。

### 1.2 Release Gate ≠ Research Gate（铁律）
研究线（MVSK/qlib/GNN/ERL/S12/Alpha Registry/regime）**不得成为发布的隐式前置**。明确 Blocker 白名单（仅 D11/门禁三件套/行数/覆盖率/冻结执行可阻塞发布），其余一切评估只产出"切换决策材料"。防的是 10 月后的经典滑坡："这个模型效果不错，要不要顺便塞进发布？"

**配套**: Health Score 是 Dashboard 不是 Gate——评分高不豁免任何硬门禁 FAIL。

### 1.3 不可逆动作拆批次（R-3）
多项不可逆生产切换（资金升级/防御层/模型切换）**不得捆绑同一日**——故障归因困难。拆为：冻结 → RC 验证 → 配置锁定 → rehearsal → 软件发布（资金/模型不动）→ 独立生产切换窗（各项独立 Go/No-Go + 独立回滚预案）。

### 1.4 Change Budget + Kill Criteria（冻结的机械化）
- 冻结决策从"战略文字"变"机械可检"：flag 基线快照 + 新增 enable 检测 + 模型落盘 mtime 检测入 debt gate（D12），窗口外 PASS 待激活、窗口内 fail-closed。
- 每个研究项目登记 **Kill 条件**（Δ夏普≤0 / CPCV 不显著 / 成本超预算…），触发即归档不续期——系统需要"自动淘汰能力"而非只自动增加能力。

### 1.5 编号体系
存量 Wave/Sprint/P/D/G 编号保留不重编（重编成本>收益，历史指针全断）；新增任务用 `Release → Stream → Gate → Task` 四层。

## 二、测试写源治理三层防线

**根因模式**: 测试直调生产函数（尤其带默认空参的）→ 数据写入生产 jsonl/json。
**实锤方法**: 生产文件里出现 **timestamp 与测试运行时间同批**的记录 = 测试污染（按 ts 精确匹配清理，不按 date 猜）。

**三层防线**:
1. **隔离层**: conftest Tier-2 登记不能只覆盖 scripts 层——utils 层模块级写路径常量（如 `MVSK_SHADOW_REPORT_PATH`）同样会被测试触发写入。
2. **防御层**: 写入方对空/非法入参 fail-closed（默认参数 `trade_date=""` 直写会落 `{"date":""}` 脏记录）。
3. **卫生层**: 溯源清理用 timestamp 批次匹配；计数幂等（同日替换而非 append——history 记录数与计数器错位即幂等缺失信号）。

## 三、入口脚本 sys.path 铁律（验证环境 ≠ 生产环境）

**坑**: `python scripts/foo.py` 时 `sys.path[0]` = scripts/ 目录，项目根不在路径上 → `import utils.*` 全挂。
**放大器**: 脚本内 fail-open 门控（"日历不可用按交易日跑"）在 import 失败时**形同虚设**，静默降级 skeleton。
**实锤后果**: S6 线若不修，cron 起 30 天全骨架（记录"正常积累"表象下对比从未发生）。

**铁律**:
1. **cron/CLI 入口脚本必须显式 `sys.path.insert(0, PROJECT_ROOT)`**——不能依赖调用环境。
2. **验证必须用与生产完全一致的调用方式**（pytest/-c 环境 sys.path 含项目根 ≠ CLI 直跑）——与"门禁负向验证须用 CI 同格式入参"教训同族。
3. **系统性排查法**: AST 遍历入口脚本——有 `__main__` ∧ import 顶层包 ∧ 无 'sys.path' 字样 → 缺口（全仓扫描仅 2 处残留即证明可行）。

## 四、shadow 线有效性判据："对比真的会发生吗"

评估任何 shadow/对比线之前，先验证两个前提（"记录在正常积累"表象 ≠ 评估有效）：
1. **消费端与信号标的相交**: 消费端是 ETF、模型预测是个股 → 每日全走 fallback，Δ对比统计上无意义（qlib 双缺陷之一）。
2. **信号是逐日新生成**: 训练时的 OOS 静态快照冒充每日信号（qlib 缺陷之二）——快照日期截至过去即铁证。

**附带判据**: 降级/fallback 记录的"骨架比例"应持续暴露（记录 status 分布），全骨架 = 线无效前兆。

## 五、实盘绩效目标的数学诚实

- "每天稳定盈利 X 元" = 要求日度夏普 ≥1.645 → 年化夏普 ≈26（X=1000/300万 口径）——**全球不存在**（文艺复兴 ≈6-8），所有"日化"承诺皆为庞氏结构。
- 诚实口径（用户拍板 2026-09-05，已入 ROADMAP `release.performance_targets`）: 年化 8~18% + 最大回撤 ≤10%（预算线）+ 月度胜率 ≥70%；允许亏损日。
- **预算线与硬停止分层**: 预算线（10%，突破=评估/复盘/影响升级判定）≠ 硬停止（15%，运行时 Kill Switch）——两者共存是分层设计，不是配置不一致；权益策略回测回撤 9.95% 时预算线贴脸是"预算"语义的正常状态。
- **验收基础**: 真实资金影子绩效（20万→100万→200万灰度），非回测——回测打八折是常态。
- 期货账户定位 = 对冲/套利载体（非独立收益机器），杠杆纪律 ≤2 倍。

## 六、审计方法增量（相对既有 SOP）

1. **因果实验隔离法**: 怀疑自己改动引入回归时，临时移除嫌疑改动复跑对照（须先备份、跑完立即恢复、不触碰他人工作树）——本案排除 conftest 嫌疑只用了 3 分钟。
2. **quotePath 假象**: `git ls-files` 中文/emoji 路径八进制转义会让 py_compile 报 OSError 假象——统一 `-c core.quotePath=false` + `encoding='utf-8'`。
3. **证据链台账**: 任何 F 数字必须指回 `reports/test_runs/<run_id>/failures_shard*.txt`，失败归类从清单生成而非记忆。
4. **flaky 判据升级**: "单跑过/全量挂"不再自动归为顺序依赖——先做因果实验排除真实回归（本案 09-04 的"单跑 2P"结论今日已不成立）。
