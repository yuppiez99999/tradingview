## 2. SC-4 · IC_IR 假告警（哨兵值被当退化）

### 2.1 根因链（三个语义混用的缺陷叠加）

1. `delayed_label_tracker._compute_ic_ir` 在**有效 IC 天数 < 2** 时返回 `0.0` —— 这是**哨兵值**，不是实测值。
2. `drift_shadow_integrator` 的门禁只检查 `n_observed >= 20`（**预测计数**），未检查**有效 IC 天数** → 哨兵 `0.0` 通过门禁 → 每日误报「基线 0.88 → 0.0 退化」。自 08-20 起持续 >3 周从未自愈（对真实退化形成**掩蔽**，即告警疲劳）。
3. 退化量用 `abs(baseline - current)` → **改善也被算作退化**。实测 `ic_ir` 0.88 → 1.30（大幅改善）被报 `degradation=0.42`。

### 2.2 修复（三处，口径共享）

- `delayed_label_tracker`：拆出 `_daily_ic_series()`，`_compute_ic_ir` 与新增 `DelayedMetrics.n_ic_days` **共用同一份口径**（避免"算 IC_IR"与"判样本是否够"两处各自实现而漂移）。
- `drift_shadow_integrator`：新增 `MIN_IC_DAYS_FOR_ALERT = 2`（与 `_compute_ic_ir` 的 `< 2 -> 0.0` 对齐）+ `IntegrationResult.ic_ir_measurable`；`abs()` → **带符号**（正 = 退化）。不可测量时登记 `ic_ir_not_measurable`（降级信息），**不报退化**。
- `utils/health/score_engine.py`（**连带消费方**）：`ic_ir_measurable=False` 走**中性基线**（不扣分）。若不改这里，去掉假告警反而会让健康分从 85 掉到 70（把"未知"当"最差"），属于"修了假告警却引入新的假扣分"。

### 2.3 向后兼容

老产物无 `ic_ir_measurable` 键 → 默认 `True`（按可测量处理），行为与修复前一致。

## 3. SC-3 · 约束→归一化顺序（`portfolio_builder`）

### 3.1 缺陷

`apply_risk_constraints` 顺序为「砍帽 → **全局**归一化」：
1. 归一化把刚压到上限的权重**重新抬超**（`total_w < 1` 时）；
2. 全局归一化还把**层权重配比**（0.20/0.30/0.50）抹平为按只数等权。

实测（smoke 3/3/4，3 行业）：`max_single = 0.10`（**2× 上限 5%**）、`max_industry = 0.40`（**1.6× 上限 25%**）。
该函数此前**零测试覆盖**。

### 3.2 修复

- `_redistribute_within_layer()`：**层内**迭代收敛（层总权重 = 层配比，每只 ≤ 单股上限；砍帽后把缺口按剩余容量补回未到帽的标的，迭代至收敛）。
- `_enforce_industry_cap()`：行业上限作用于**全组合**，且**优先于**层配比凑满（风控铁律：宁可总权重 < 1，也不违反行业硬上限）。
- 不可行（层内 `n × cap < 层权重`）/ 未收敛 → **显式 WARNING**，不静默放行。

### 3.3 修复前后实证

| 场景 | 修复前 | 修复后 |
|---|---|---|
| smoke 3/3/4 max_single | **0.10**（2× 上限） | 0.05 ✓ |
| smoke 3/3/4 max_industry | **0.40**（1.6× 上限） | 0.20 ✓ |
| 满配 20/30/50（10 行业）total | （层配比被抹平） | **1.0** ✓ / 单股 0.01 / 行业 ≤0.25 ✓ |
| 满配 层配比 | 被全局归一化破坏 | **0.20 / 0.30 / 0.50** ✓ |
| 层内不可行 | 静默抬超上限 | 给满上限 + WARNING |
