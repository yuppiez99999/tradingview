# PARA 分类法

> PARA 是 Tiago Forte 提出的个人信息管理框架，把所有信息按「可行动性」分成四类。

---

## 四个分类

### 1️⃣ Projects 项目

**正在推进、有终点的事。**

判定标准：能不能说清「完成」是什么样？

```
特征：有明确目标、有截止日期（或期望完成时间）
例子：搭建第二大脑、准备 PPT、完成产品 V2、学完一门课
存放：1-Projects/
```

每个项目都应该：
- 有目标（什么是「完成」）
- 有关键任务（拆成可执行步骤）
- 有状态追踪（active / paused / done）

---

### 2️⃣ Areas 领域

**需要持续维护的责任范围，没有终点。**

判定标准：「这是我需要长期负责的事吗？」

```
特征：没有「完成」，只有「维护」
例子：健康、财务、职业发展、家庭、写作习惯、某项专业技能
存放：2-Areas/<领域名>/
```

领域下可以按子主题再分文件夹，例如：
- `2-Areas/健康/运动/`
- `2-Areas/健康/饮食/`
- `2-Areas/职业/技能提升/`

---

### 3️⃣ Resources 资源

**未来可能用到的参考资料，感兴趣但还不紧迫的主题。**

判定标准：「我现在不一定用，但将来可能查阅」

```
特征：从外部收集的信息，用于参考和灵感
例子：读书笔记、技术文章、工具清单、菜谱、旅行攻略
存放：3-Resources/<主题>/
```

常见子目录：
- `3-Resources/技术笔记/` — 编程、AI、工具使用
- `3-Resources/读书笔记/` — 按书名组织
- `3-Resources/文章剪藏/` — 网页、公众号、知乎
- `3-Resources/工具清单/` — 软件推荐、配置备忘

---

### 4️⃣ Archives 归档

**前三类里失去活性的内容。**

判定标准：完成的项目、放弃的兴趣、过期的资料

```
特征：不再需要日常关注，但保留备查
例子：已交付的项目、过去的旅行计划、已离职的公司信息
存放：4-Archives/
```

**归档不等于删除** — 保留所有记录，将来可能有用。

---

## 分类决策流程

```
收到一条新信息
    │
    ├─ 有明确目标和截止日期？→ Projects
    ├─ 是我要长期负责的事？  → Areas
    ├─ 是参考资料？           → Resources
    ├─ 已经完成/不活跃了？    → Archives
    └─ 拿不准？              → 0-Inbox（先放着）
```

## 整理规则

1. **一拿不准就进 Inbox**，别在分类上卡住，保持捕获流畅
2. **每周回顾时整理 Inbox**，把内容分发到 PARA
3. **项目完成即归档**，移到 `4-Archives/`，别删
4. **领域只进不出**，领域文件夹永远存在
5. **资源按主题聚合**，方便日后检索
