## 第 2 步:创建 IAM 子账号与 AK/SK(15 分钟)

> **为什么要子账号?** 用 root 账号的 AK/SK 有全权限,不安全。IAM 子账号只给需要的权限。

### 2.1 创建 IAM 用户

1. 控制台 → 左上角菜单 →"统一身份认证服务"(IAM)
2. 左侧"用户"→"创建用户"
3. 填写:
   - 用户名:`qt-admin`
   - 凭证类型:勾选"编程访问"(会生成 AK/SK)+ "管理控制台访问"(可登录控制台)
   - 密码:设一个强密码,记下来
   - 用户组:选"admin"(或新建组并赋所有权限,简化教程)
4. 点"确定"

### 2.2 获取 AK/SK

创建成功后,页面会显示 **AK** 和 **SK**(Access Key / Secret Key):

    AK:      XXXXXXXXXX...
    SK:      XXXXXXXXXX...

**⚠️ 立即复制保存!SK 只显示这一次,关掉就再也看不到。** 建议存到 Mac Keychain:

    security add-generic-password -a yuppiefree2025 -s huaweicloud_ak -w "你的AK"
    security add-generic-password -a yuppiefree2025 -s huaweicloud_sk -w "你的SK"

验证能读出:

    security find-generic-password -a yuppiefree2025 -s huaweicloud_ak -w  # 应输出 AK

### 2.3 故障排查

| 问题 | 解决 |
|---|---|
| 没勾"编程访问",没有 AK/SK | IAM → 用户 → qt-admin →"修改"→ 勾选编程访问 → 重新生成 |
| SK 忘了没保存 | IAM → 用户 → qt-admin →"访问密钥"→ 删除旧的 → 新建 |
| 权限不够 | IAM → 用户组 → admin → 权限 → 赋"OBS OperateAccess"+"ModelArts FullAccess"+"SWR FullAccess" |

## 第 4 步:创建 OBS 桶(10 分钟)

> OBS(对象存储)用来存训练数据和模型,类似云上的无限大硬盘。

### 4.1 控制台创建

1. 控制台 → 左上角菜单 →"对象存储服务"(OBS)
2. 左侧"并行文件系统"或"桶"→"创建桶"
3. 填写:
   - 桶名:`qt-data`(全局唯一,若被占用用 `qt-data-你的用户名`)
   - 区域:`华东-上海一`(对应 cn-east-3)
   - 桶分类:**标准存储**
   - 存储类别:标准
   - 桶策略:私有
   - 默认加密:可选开启
4. 点"立即创建"

再创建一个桶 `qt-models`(存训练输出的模型)。

### 4.2 CLI 验证

    hcloud OBSListBuckets

**预期:** 列出 `qt-data` 和 `qt-models`。

### 4.3 故障排查

| 问题 | 解决 |
|---|---|
| 桶名被占用 | 桶名全局唯一,加后缀如 `qt-data-yuppiefree2025` |
| 没开通 OBS | 控制台 → OBS → 点"开通服务"(需实名认证) |

## 第 5 步:安装 obsutil 并上传训练数据(20 分钟)

> obsutil 是 OBS 的命令行工具,比 CLI 上传大文件更快。

### 5.1 下载安装 obsutil

    cd ~/Downloads
    curl -O https://obs-community.obs.cn-north-1.myhuaweicloud.com/obsutil/current/obsutil_darwin_arm64.tar.gz
    tar xzf obsutil_darwin_arm64.tar.gz
    sudo mv obsutil /usr/local/bin/
    obsutil version

**预期:** 输出 obsutil 版本号。

> 若上面的 URL 失效,去 https://support.huaweicloud.com/utiltg-obs/obs_11_0001.html 下载 Mac ARM 版。

### 5.2 配置 obsutil

    obsutil config \
      -ak=$(security find-generic-password -a yuppiefree2025 -s huaweicloud_ak -w) \
      -sk=$(security find-generic-password -a yuppiefree2025 -s huaweicloud_sk -w) \
      -endpoint=obs.cn-east-3.myhuaweicloud.com

**预期:** `Set obsutil config successfully!`

### 5.3 上传训练数据

上传 Qlib 全 A 股数据(270MB,约 2 分钟):

    obsutil cp -r -f ~/QuantData/qlib_data/ obs://qt-data/qlib_data/

**预期输出:**

    Upload [succeeded] [count: xxx], [failed: 0], [cost: xxx ms]
    Total count: xxx, size: 270.0MB

上传 parquet 行情片段(40MB):

    obsutil cp -r -f ~/QuantData/data_cache/ obs://qt-data/data_cache/

上传配置文件:

    obsutil cp -r -f ~/28-终极量化交易系统8.4/config/  obs://qt-data/config/

### 5.4 验证上传

    obsutil ls obs://qt-data/ -limit=10

**预期:** 列出 `qlib_data/`、`data_cache/`、`config/`。

### 5.5 故障排查

| 问题 | 解决 |
|---|---|
| `obsutil: command not found` | `sudo mv obsutil /usr/local/bin/` 没成功;用 `~/Downloads/obsutil` 全路径调用 |
| `Endpoint does not exist` | endpoint 拼错;华东是 `obs.cn-east-3.myhuaweicloud.com` |
| `Access Denied` | AK/SK 错或权限不够;回第 2 步检查 |
| 上传慢 | 家宽限制;270MB 正常 2–5 分钟,耐心等 |
| `obsutil_darwin_arm64.tar.gz` 下载失败 | 浏览器手动下载,放到 ~/Downloads/ 再解压 |

## 第 7 步:本地构建训练镜像(30 分钟)

> 把训练代码打包成 Docker 镜像。这是最关键的一步。

### 7.1 准备 Dockerfile

在项目根目录创建 `cloud/docker/Dockerfile.qlib-trainer`:

    mkdir -p ~/28-终极量化交易系统8.4/cloud/docker

用编辑器创建 `~/28-终极量化交易系统8.4/cloud/docker/Dockerfile.qlib-trainer`,内容:

    FROM python:3.11-slim
    RUN pip install --no-cache-dir uv
    WORKDIR /app

    COPY pyproject.toml uv.lock ./
    RUN uv sync --frozen --no-dev

    COPY ms_strategy/cloud_train/ ./ms_strategy/cloud_train/
    COPY ms_strategy/training/ ./ms_strategy/training/
    COPY qlib/ ./qlib/
    COPY utils/ ./utils/
    COPY config/ ./config/
    COPY configs/ ./configs/
    COPY lgb_trainer/ ./lgb_trainer/
    COPY lgb_enhanced_trainer.py lgb_tscv_trainer.py autolearn_trainer.py ./

    ENV QT_PLATFORM=cloud
    ENV QLIB_DATA_DIR=/cache/data/qlib_data/cn_data
    ENV QUANT_DATA_ROOT=/cache/data

    CMD ["uv", "run", "python", "ms_strategy/cloud_train/modelscope_train.py"]

### 7.2 创建 .dockerignore

创建 `~/28-终极量化交易系统8.4/.dockerignore`:

    data/
    data_cache/
    models/
    logs/
    reports/
    output/
    .venv/
    __pycache__/
    .pytest_cache/
    .mypy_cache/
    .ruff_cache/
    game/
    games/
    *.ps1
    cache/

### 7.3 构建镜像(关键!注意架构)

**因为云上是 x86_64,Mac M5 Max 是 ARM64,必须指定 `--platform linux/amd64`:**

    cd ~/28-终极量化交易系统8.4
    docker build --platform linux/amd64 \
      -t swr.cn-east-3.myhuaweicloud.com/qt/qt-qlib-trainer:latest \
      -f cloud/docker/Dockerfile.qlib-trainer .

**预期:** 输出一堆 `Step x/x : ...`,最后 `Successfully tagged swr.cn-east-3.myhuaweicloud.com/qt/qt-qlib-trainer:latest`

**耗时:** 10–20 分钟(首次需下载 python:3.11-slim + 装依赖,后续有缓存会快)。

### 7.4 验证镜像

    docker images | grep qt-qlib-trainer

**预期:** 列出镜像,大小约 1–2GB。

### 7.5 故障排查

| 问题 | 解决 |
|---|---|
| `docker build` 卡在 `uv sync` | 网络慢;加 `--no-cache` 重试;或先 `docker pull python:3.11-slim` |
| `platform linux/amd64 not supported` | 确认 Docker Desktop → 设置 → 勾选"Use Rosetta 2 for x86/amd64 emulation";或 `docker buildx build --platform linux/amd64` |
| `COPY failed: file not found` | 某些模块路径不对;检查 `ls ~/28-终极量化交易系统8.4/ms_strategy/cloud_train/` 存在 |
| 构建太慢 | `.dockerignore` 没生效,检查是否排除了 `data/` `models/` 等大目录 |
| `uv: command not found` in 镜像 | Dockerfile 里 `pip install uv` 失败;改用 `RUN pip install uv==0.4.x` |

## 第 10 步:提交第一个训练作业(30 分钟)

> **这是高潮!** 提交一个 Qlib csi300 LightGBM 训练作业。

### 10.1 准备作业配置 JSON

创建 `~/28-终极量化交易系统8.4/cloud/modelarts/modelscope_csi300.json`:

    mkdir -p ~/28-终极量化交易系统8.4/cloud/modelarts

内容(把 `qt-data` 换成你的实际桶名):

    {
      "metadata": {
        "name": "qt-modelscope-csi300",
        "description": "Qlib csi300 LightGBM 训练"
      },
      "algorithm": {
        "image": "swr.cn-east-3.myhuaweicloud.com/qt/qt-qlib-trainer:latest",
        "command": "uv run python ms_strategy/cloud_train/modelscope_train.py --data-dir /cache/data/qlib_data/cn_data --market csi300 --start 2015-01-01 --end 2026-08-14 --train-end 2024-12-31 --valid-end 2025-06-30 --model lightgbm --num-leaves 128 --boost-round 500 --learning-rate 0.02 --max-depth 8 --output /cache/output"
      },
      "spec": {
        "resources": {
          "flavor": "modelarts.bm.8c32g.cpu",
          "pool": "public"
        },
        "volumes": [
          {
            "nfs": {
              "id": "obs-qt-data",
              "src": "obs://qt-data/",
              "dest": "/cache/data",
              "read_only": false
            }
          },
          {
            "nfs": {
              "id": "obs-qt-models",
              "src": "obs://qt-models/",
              "dest": "/cache/output",
              "read_only": false
            }
          }
        ]
      }
    }

### 10.2 控制台提交(推荐首次用控制台,直观)

1. ModelArts →"训练管理"→"训练作业"→"创建训练作业"
2. 填写:
   - 作业名称:`qt-modelscope-csi300`
   - 算法来源:**自定义**
   - 镜像:`swr.cn-east-3.myhuaweicloud.com/qt/qt-qlib-trainer:latest`(从 SWR 选)
   - 启动命令:粘贴 JSON 里 `command` 的内容:

         uv run python ms_strategy/cloud_train/modelscope_train.py --data-dir /cache/data/qlib_data/cn_data --market csi300 --start 2015-01-01 --end 2026-08-14 --train-end 2024-12-31 --valid-end 2025-06-30 --model lightgbm --num-leaves 128 --boost-round 500 --learning-rate 0.02 --max-depth 8 --output /cache/output

   - 资源池:**公共资源池**
   - 资源规格:`modelarts.bm.8c32g.cpu`(8 核 32G CPU)
   - 计算节点个数:`1`
   - 数据存储:**OBS** → 桶 `qt-data` → 本地路径 `/cache/data`
   - 训练输出:**OBS** → 桶 `qt-models` → 本地路径 `/cache/output`
   - 运行参数:可留空
3. 点"立即创建"→"是"

### 10.3 查看作业状态

1. ModelArts →"训练作业"→ 看到 `qt-modelscope-csi300`
2. 状态变化:`初始化` → `运行中` → `已完成`(或 `失败`)

**预期:** 5–30 分钟后状态变"已完成"。

### 10.4 查看训练日志

1. 点作业名 →"日志"页签
2. 应看到:
   - `qlib.init` 成功
   - Alpha158 特征工程输出
   - LightGBM 训练进度
   - IC / Rank IC / IC IR 指标
   - 模型保存到 `/cache/output/`

### 10.5 故障排查

| 问题 | 解决 |
|---|---|
| 状态卡"初始化" | 公共池排队;等 5–10 分钟;或换规格 |
| 状态"失败" | 点作业看日志,常见原因见下 |
| 日志 `ModuleNotFoundError: No module named 'qlib'` | 镜像里没装 pyqlib;Dockerfile 加 `RUN pip install pyqlib` 重新构建推送 |
| 日志 `FileNotFoundError: /cache/data/qlib_data/cn_data` | OBS 数据没挂载对;检查第 10.2 的数据存储配置,桶名/路径要对 |
| 日志 `OBS access denied` | IAM 权限缺 OBS;回第 2 步加 `OBS OperateAccess` |
| 日志 `qlib.init failed` | `qlib_data/cn_data/` 数据不完整;回第 5 步确认上传了 `calendars/` `instruments/` `features/` |
| 作业超时 | 训练数据量大;把 `--boost-round 500` 改小如 `100` 先跑通 |

## 全局故障排查速查

| 现象 | 最可能原因 | 解决 |
|---|---|---|
| 任何 `access denied` | IAM 权限不够 | 第 2 步加权限 |
| 任何 `not found` | 桶名/路径/镜像名拼错 | 对照教程逐字检查 |
| `docker build` 失败 | 网络或 Dockerfile 语法 | 看报错行,对照第 7 步 |
| 训练作业失败 | 看日志 | 第 10.4 步,日志会告诉具体原因 |
| 训练慢 | 数据大/规格低 | 先用小 `--boost-round` 跑通,再调大 |
| 费用超预期 | 作业没释放 | ModelArts → 训练作业 → 确保状态"已完成"非"运行中" |
