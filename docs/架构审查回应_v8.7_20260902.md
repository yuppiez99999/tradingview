### 纠正 1：#5 归因系统不是"缺失"，而是"在跑但数据失真"（严重度升级）

审查原判断：*"目前缺少一个机构级模块：收益归因系统"*。

**实态**：归因模块族完整且已挂进每日 EOD 链路。

| 证据 | 位置 |
| --- | --- |
| EOD 唯一无条件调用点 | `15_每日工作流/run_daily_eod_workflow.py:1744` |
| 阶段函数定义 | `run_daily_eod_workflow.py:1004` `run_phase4_55_attribution()` |
| 引擎导入 | `run_daily_eod_workflow.py:1029` `from utils.pnl_attribution_engine import PnLAttributionEngine` |
| 报告落盘 | `run_daily_eod_workflow.py:1082` `engine.save_report(attribution)` |
| 产物 | `reports/pnl_attribution/pnl_attribution_{date}.json`（实测 12 个日期，2026-08-18 ~ 09-01） |
| 能力模块 | `utils/attribution/brinson_attribution.py`（Brinson-Fachler 三效应）、`utils/attribution/factor_attribution.py`（Barra 10 风格 + 8 行业）、`utils/attribution/daily_panel.py`（三合一 Facade） |

**但核验发现一个比"缺失"更严重的问题 —— EOD 传入的归因输入是硬编码合成常量：**

```python
# 15_每日工作流/run_daily_eod_workflow.py:1047-1078
benchmark_returns = [portfolio_ret * 0.8]              # 基准 = 组合收益 x 0.8
factor_returns = {
    "momentum": [portfolio_ret * 0.3],
    "reversal": [-portfolio_ret * 0.1], ...            # 因子收益 = 组合收益 x 固定系数
}
sector_returns = {
    "科技": [portfolio_ret * 0.4], ...                 # 行业收益 = 组合收益 x 固定系数
}
trading_costs=0.0, funding_cost=0.0                    # 交易成本硬编码为 0
```

**后果**：归因报告每天稳定产出、字段齐全、看起来正常，但所有归因数字都是组合收益的算术变形，不反映真实的 Beta / 行业 / 因子贡献。这比"没有归因"更危险——它会让"模型赚钱还是行情赚钱"这个问题得到**确定但错误**的答案。

**六维度实测覆盖**：

| 维度 | 判定 | 证据与缺口 |
| --- | --- | --- |
| 市场 Beta | 部分覆盖 | `beta_pnl` 落盘（如 `pnl_attribution_2026-09-01.json` 中 3101.27）；但基准为 `portfolio_ret x 0.8` 合成值 |
| 行业配置 | 部分覆盖 | `sector_pnl` 落盘；EOD 传 6 个中文行业 vs 引擎 `SECTORS` 11 个不匹配，报告显示仅 4 个命中，其余 `factor_return: 0.0` |
| 因子 Alpha | 部分覆盖 | `alpha_pnl` + 7 个 `style_factors` 落盘；但为合成系数，**真实 Barra 实现 `factor_attribution.py` 未被 EOD 调用** |
| 择时 | 部分覆盖 | `pnl_attribution_engine.py:230-240` `timing_pnl = total_pnl - explained` —— 是**残差插补项**，非择时模型 |
| 期权保护 | 部分覆盖 | `hedge_pnl` 来自真实 EOD 报告（`_load_hedge_pnl_from_eod_report()` :998）；但 12 份报告中 **9 份为 0.0** |
| 交易成本 | **未覆盖** | EOD 硬编码 `trading_costs=0.0`；真实实现在 `v8.3_institutional/workflow/phases/report.py:412` 未接入 |

**附带发现**：`v8.3_institutional/daily_workflow.py:623` 仅实例化 `PnLAttributionEngine()`，**从不调用** `attribute()`；`generate_daily_report.py` 无任何归因调用。

**结论**：审查方向正确（归因确实需要重视），但缺口性质是 **数据真实性 P0 缺陷**，不是模块缺失。修复工作量远小于新建，收益极大。

### 纠正 2：#2 风险预算引擎不是"缺失"，regime 驱动能力已存在且已启用

审查原判断：*"下一步建议增加 Dynamic Risk Budget Engine（由 VIX/波动率/趋势/流动性/回撤/相关性自动调整）"*。

**实态**：系统已有两套 regime 驱动能力，且其中之一默认启用。

| 模块 | 能力 | 证据 |
| --- | --- | --- |
| `utils/regime_aware_allocator.py` | `RegimeClassifier`（VIX 阈值 low_vol/normal/high_vol）+ `RegimeConfig`（risk_aversion / max_weight / **defense_boost / offense_boost**）+ Ledoit-Wolf 协方差收缩 + `allocate(returns, vix, defense_mask, offense_mask)` | L48 `Regime`、L77 `RegimeClassifier`、L170 `RegimeConfig`、L252 `RegimeAwareAllocator` |
| `utils/alpha/vol_regime_weighter.py`（1033 行） | `sense_regime(vix_value, daily_returns, psi_value, current_drawdown)` 多指标判定（VIX + 已实现波动率 + PSI + 回撤，含一致性交叉校验）→ 风格权重乘子 → `enforce_constraints`（单票上限/行业上限/现金下限）→ `emit_suggestion` 落盘 → `apply_to_portfolio(yaml_path, dual_signature)` **需双签** | L385 `sense_regime`、L537 `compute_weights`、L656 `enforce_constraints`、L897 `apply_to_portfolio` |
| `config/feature_flags.yaml:36-40` | `USE_VOL_REGIME_WEIGHTER: default: true`（**已启用**） | — |
| `utils/risk_budget_engine.py` | 事前 VaR 校验引擎（组合 VaR95/99 + 单标的 VaR + 集中度 + 回撤预算 + 预算使用率），构造参数为静态阈值（max_daily_var_95=0.035 / max_single_var_95=0.012 / max_drawdown=0.15 / max_weight=0.15），**不接受 regime 输入** | L61-153 |

**真实缺口（精确化）**：

1. **两套能力未打通** —— `risk_budget_engine`（VaR 侧风险校验）与 `vol_regime_weighter` / `regime_aware_allocator`（配置侧 regime 响应）彼此独立，无数据流串联。风控是"给定目标组合做校验"，配置是"给定 regime 调权重"，两者未形成闭环。
2. **缺资产大类三分类预算映射** —— 审查要求的"股票/ETF/期权保护 三类资产比例"（Bull 80/15/5、Normal 60/30/10、Crisis 20/50/30），现有实现是**风格权重乘子 + 防守/进攻资产 boost**，层面不同。系统内尚无 `regime → {股票, ETF, 期权保护}` 的显式映射表。

**结论**：不需要从零新建 Dynamic Risk Budget Engine，工作量降为"打通 + 补映射表"。
