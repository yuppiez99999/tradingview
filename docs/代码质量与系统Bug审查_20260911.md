### P1-1 建仓流水被静默短路（每日 09:00「假完成」，已复现）

**位置**（根因 + 三处消费方）：
- 根因：`auto_trade_plan_500w_2026-2030.json` 仅存在于 repo 根 `trade_plans/`（本地副本）；`v8.3_institutional/trade_plans/` 下的版本于 2026-08-08 从 git 删除（commit `8902ccb5`）后未归位。
- 消费方①：`daily_trade_executor.py:79` `TRADE_PLAN_FILE` → 指向 `v8.3_institutional/trade_plans/...`（**不存在**）→ `executor/premarket.py:58` `load_trade_plan()` 返回空 `{"stock_etf_account": {"positions": []}}` → `generate_instructions` 直接返回 `{"status":"completed","reason":"所有标的已建仓完成"}`（`executor/premarket.py:766-778`）。
- 消费方②：`reporting/next_day_planner.py:60-88` 同一缺失路径 → 返回 `(None, error)`，日报「次日计划」降级。

**复现证据**（只读核验，两条即可重做）：

**影响**：

- 「假完成」与本项目铁律「缺数据 = 通过的假 PASS 必须消灭」直接冲突。

**建议（需先拍板）**：

- 无论哪种，`load_trade_plan()` 的「空计划 → 假完成」应改为显式错误态（fail-closed / 告警），不允许静默通过。
