## 一、治理背景

用户提问："为什么 check 系统代码质量和 bug 后，还有很多地方无法跑通？"

诊断结论：此前的质量检查产出的是**静态扫描清单**（lint、路径硬编码、LF/CRLF 等），而"跑不通"的根因是五类**运行时行为缺陷**——静态扫描天然看不见，且既有测试自身也存在盲区（打外网、硬编码日期、隐式全局依赖），导致问题被测试绿掩盖。

| # | 根因类别 | 典型症状 |
|---|---|---|
| P0-1 | 入口脚本无 CLI 契约 | 无参运行直接走默认分支（可能误触发交易）；被 `--help` 探测时直接开跑 |
| P0-2 | 测试隐式打外网 | smoke 测试 30s 超时挂起、CI 结果不可复现 |
| P0-3 | import 副作用 | 启动即卡 5-22s（包级 eager import 拉起 scipy/torch/qlib） |
| P1-1 | 模式开关散落 6 处互不知晓 | 编程调用漏传 dry_run 即触发实盘路径，无全局一键干跑 |
| P1-2 | 降级不闭环 | `trade_execution.yaml` 缺失 → 风控参数走硬编码默认值静默继续 |

验证：4 个脚本 `--help` 零业务动作秒级返回；dry-run 实跑前后关键文件时间戳零变化；130 个既有测试全绿。

### P0-2 测试外网隔离（QUANT_OFFLINE）

- `utils/external_data_source.py` 新增 `_session_get()` 统一网络入口，`QUANT_OFFLINE=1` 时抛 `ConnectionError` → 复用各 API 类**既有 fail-safe** 优雅降级（零新代码路径）；8 处调用点替换
- `tests/conftest.py` 默认 `QUANT_OFFLINE=1`，`--run-integration` 保留真网；外部显式设置不覆盖
- 踩坑：`_session_get` 内部需动态属性查找 `_SESSION.get(...)`，否则破坏 34 个 `patch("_SESSION.get")` 既有 mock

效果：test_er23 smoke 30s 超时 → 12 passed in 8s；全量 smoke+unit 37 failed → 17 failed。**生产环境不设该变量，行为零变化。**

### P0-3 import 副作用清零（PEP 562 懒加载）

用 `-X importtime` 实测定位真凶（**纠偏**：慢的不是 data_provider 本体，仅 4ms）：

| 罪魁 | 拉起 | 影响 |
|---|---|---|
| `utils/__init__.py` eager import 9 个模块 | scipy.stats 2.2s + pandas 1.5s | 任何 `import utils.*` 付 5.3s |
| `utils/alpha/__init__.py` eager 加载 qlib_signal_adapter | qlib + torch + lightgbm ~5s | 纯网络模块也被拖累 |

修复：`__getattr__` 懒 re-export 映射表（57 个符号），HC-1 re-export 契约 100% 保留。

| 入口 | 前 | 后 |
|---|---|---|
| `import utils` | 5.26s | **0.01s** |
| `generate_daily_report` | 22.7s | **0.44s**（-98%） |
| `system_integration` | 8.4s | 1.7s |

踩坑：`__getattr__` 内 `from . import X` 会递归触发自身 → 必须 `find_spec`；别名 re-export（如 `flag_is_enabled`←`is_enabled`）需映射表记录原名。

### P1-1 统一三态开关（utils/runtime_mode.py）

单一真相源：`is_offline()` / `is_dry_run()` / `is_sandbox()` 分别对应 `QUANT_OFFLINE` / `QUANT_DRY_RUN` / `QUANT_SANDBOX`，三态独立可组合，优先级 `set_mode()` > env > False。三层接入：网络层委托、4 个 CLI 入口解析后全局广播、`DailyWorkflow.__init__` 与全局开关取或（漏传参数兜底）。新增 25 个单测。

```bash

```

### P1-2 配置缺失静默降级闭环

实锤发现：`config/trade_execution.yaml` **根本不存在**——执行器全部风控参数（单日限额/价格保护带/止损熔断/回撤熔断）长期走硬编码默认值；`stop_loss_monitor` 规则文件缺失时返回 `{}` = 零止损规则，均静默继续。

闭环三件套：
1. **统一降级审计** `utils/degradation_audit.py`：`record_degradation()` 追加写 `reports/degradation_log.jsonl`，进程内去重，审计自身 fail-safe
2. **strict 能力**：`get_config(strict=True)` 抛 `ConfigNotFoundError`；`QUANT_STRICT_CONFIG=1` 时风控配置缺失**硬失败**（防基于默认风控线交易）
3. 两个风控关键点接入（daily_trade_executor / stop_loss_monitor 4 个路径）

### 存量功能 bug（13 个测试失败同根因 + 收尾 4 项）

## 四、沉淀的教训（已记入 cairn/LOG.md）

1. **带 `eval_date` 参数的回溯窗口必须锚定该参数而非 now**；测试硬编码"相对今天"的日期是定时炸弹
2. **`__file__` 相对定位 + 拼两点是泄漏温床**——同一文件两处同款 bug 证明是系统性隐患，新代码应 `_PROJECT_ROOT` 绝对锚定
3. **`__getattr__` 懒加载内禁用 `from . import X`**（递归触发自身），须用 `find_spec`
4. **mock patch 必须走动态属性查找**，缓存方法引用会破坏既有 mock
5. **静态扫描 ≠ 可运行**：测试打外网、隐式全局依赖会让"测试绿"掩盖运行时缺陷
6. **降级必须闭环**：静默降级 + 无审计 = 生产裸奔（风控参数走默认值数月无人知）
