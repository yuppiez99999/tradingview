## 2. 两条路径评估

### 路径 A：Wind 终端开通期权数据权限

| 维度 | 评估 |
|------|------|
| 可行性 | 需用户向 Wind 申请期权数据权限（可能涉及额外费用） |
| 覆盖范围 | Wind 终端期权链覆盖全市场 ETF 期权（含 159915） |
| 数据质量 | 最高（含 Greeks/IV 期限结构/成交量/持仓量） |
| 代码改动 | `_fetch_from_wind()` 当前恒 `return None`（Wind MCP **无** ETF 期权链接口）；需改用 Wind 终端 SDK（非 MCP） |
| 时间线 | 取决于用户申请进度 |
| 成本 | Wind 期权数据模块年费（待询价） |

**关键限制**：Wind **MCP** 无 ETF 期权链接口（代码注释已确认）。路径 A 需用 Wind **终端 SDK**（WindPy），非 MCP 路径。

### 路径 B：券商端期权链导出 + BS 反解 IV（过渡方案）

| 维度 | 评估 |
|------|------|
| 可行性 | **已通过 AKShare 实现**（v2, 2026-09-11） |
| 覆盖范围 | 上交所 5 只 ETF 期权（不含 159915） |
| 数据质量 | 中（行权价/权利金/到期月真实，IV 由 BS 反解，无成交量/持仓量） |
| 代码改动 | **已完成**（`utils/option_data_fetcher.py` v2） |
| 时间线 | **已就绪** |
| 成本 | 零（AKShare 免费） |

**当前缺口**：
1. 159915（创业板 ETF 期权）未覆盖 — AKShare `option_finance_board` 不含该标的
2. 交易所 T 型行情不含成交量/持仓量 → `volume=0` 表示「未知」
3. `vega` 未纳入（保持既有输出契约不变）

| 场景 | 推荐路径 | 理由 |

3. **12-10 前**：若 159915 在组合中，完成路径 A 评估（Wind 期权模块询价 + 权限申请）
4. **2027-01-01 前**：期权账户开立（50 万验资 + 知识测试 + 模拟交易记录）

### 3.3 验收标准更新

原验收：`OptionDataFetcher 能返回真实 IV 曲面（非 σ=0.20 兜底）`

**更新为**：
- ✅ 5 只已覆盖标的：`get_real_chain()` 返回真实链 + BS 反解 IV（已满足）

⇒ **路径 A 对 v9.5 无前置必要**（可后置 2027 Q1）；**但 R-12 ① 不可整体关闭**：

- **重开条件**：v9.5 参数表载「末期收官 2029Q4 起 科创/创业板可试仓 ≤30 万」⇒ 末期若纳入创业板 ETF，路径 A 须重开。
- **对现役 200 万侧，真实缺口不在"数据源未覆盖"，而在保护腿主引擎根本不取链** —— `utils/protective_put_engine.py:351` 的 IV 为**硬编码常量**（`0.30 if code in ("588080","159915") else 0.22`），故本文 §1.2「真实链已通」只对 combo 引擎成立（真实链消费方仅 `utils/etf_option_combo/combo_base.py:297` 与 `utils/execution/option_contract_resolver.py:114` 两处）。

**新增待核实（比 159915 更影响 v9.5 本身）**：v9.5 权益层 15% = **515080 中证红利 ETF**。09-13 实测 `akshare.option_finance_board("华泰柏瑞中证红利ETF期权")` → **rows=0（空表，不抛异常）**；该接口权威 symbol 全集为 9 项：华夏上证50ETF / 华泰柏瑞沪深300ETF / 南方中证500ETF / 华夏科创50ETF / 易方达科创50ETF / **嘉实沪深300ETF(159919，深市)** / 沪深300股指 / 中证1000股指 / 上证50股指。

注意 **「AKShare 未收录 ≠ 交易所无合约」**（全集含深市 159919 却**不含** 159915，而 159915 交易所确有合约）⇒ 515080 是否真有场内合约**仍须交易所/券商侧确认**；若无 ⇒ v9.5 存在 **15% 结构性不可保护敞口**（须方案层三选一处置）。**截止 09-18**。

**工程要点**：`option_finance_board` 对未知 symbol **返回空表而非异常** ⇒ 任何"空表当通过"的校验都是**假 PASS**。本系统未中招（`utils/option_data_fetcher.py:525-532` 有显式 map 缺失分支 → 记日志 + 返回 `[]` + 走降级链），但该日志为 `INFO` 级 ⇒ 建议升 `WARNING`，或把 `iv_source` 落到订单/报告以保证降级可审计。
