# 第三方项目集成总体计划 v1.0

> 生成时间: 2026-08-21 06:16
> 目标系统: 量化策略系统 v8.6 (`28-终极量化交易系统8.4/`)
> 来源: `10_第三方项目/` 高价值项目评估
> 工作流: spec-requirement → spec-design → spec-task → 实现 → 验证 (每子项独立循环)

## 0. 总体目标

将 `10_第三方项目/` 中 5 个高价值项目的能力增量集成到 v8.6 主系统，分两批：

| 批次 | 编号 | 项目 | 增量能力 | 集成点 | 前置条件 |
|------|------|------|---------|--------|---------|
| S | S1 | TradingAgents-CN | 三级新闻过滤+质量评估+相关性评分+A股中文 | `utils/signal_fusion.py` (51KB) | **需先 git clone 源码** (本地仅文档/env) |
| S | S2 | timesfm 2.5 | 零样本时序基础模型(200M,16k上下文,分位预测) | `lgb_tscv_trainer.py` + `lgb_trainer/` | `pip install timesfm[torch]` + 800MB checkpoint |
| S | S3 | ai-berkshire | 四大师对抗分析+强制结论纪律+镜子测试 | `utils/glm5_decision_engine.py` (40KB) | 18 skills 已就位, 无阻塞 |
| A | A1 | codebase-memory-mcp | tree-sitter 知识图谱+14 MCP工具+120x省token | Codex agent 配置 | 下载单二进制 + `install` |
| A | A2 | SkillSpector | 64 漏洞模式扫描第三方 skill | `githooks/pre-commit` | `pip install` + 可选 LLM |

**执行顺序**: S3 → S2 → A2 → A1 → S1 (按"无阻塞优先 + 价值递减"排列)

理由:
- S3 零阻塞且决策纪律层影响面广, 先做收益最高
- S2 依赖 pip 安装但路径清晰
- A2 安全门禁应尽早就位, 保护后续集成
- A1 工程提效, 放在集成中段让后续导航更快
- S1 需 clone 源码, 阻塞最大, 放最后

## 1. S3 — ai-berkshire 四大师决策纪律层

### 1.1 现状
- 主系统 `glm5_decision_engine.py` 已有 GLM-5 多模型路由 + 盘中决策
- 缺口: AI 输出"一方面...另一方面"式骑墙分析, 缺强制结论/价格区间/分层建议
- ai-berkshire 18 skills 已就位, 含 `investment-team.md`(四大师对抗)、`investment-checklist.md`、`quality-screen.md`、`dyp-ask.md`(段永平问)

### 1.2 集成设计
- 新增 `utils/value_discipline_layer.py` (~300行)
  - `apply_four_masters_adversarial(symbol, base_analysis) -> {buffett, munger, dyp, lixu, consensus}`
  - `enforce_decision(signal) -> {verdict: pass/fail/grey, price_band, tier_advice}`
  - `mirror_test(thesis) -> bool` (5句话说不完整 = 不买)
- 在 `glm5_decision_engine.py` 决策出口处叠加: GLM5 原始输出 → 四大师对抗 → 强制结论 → 镜子测试
- 配置: `config/value_discipline.yaml` (可开关, 默认仅对单只标的深度分析启用)

### 1.3 阶段任务
1. **spec-requirement**: 明确四大师评分维度 + 结论格式契约 + 与现有 signal_fusion 的权重
2. **spec-design**: `value_discipline_layer.py` 接口设计 + 4 个 prompt 模板 (从 ai-berkshire skills 提取)
3. **spec-task**: 拆分实现任务 (loader/adversarial/enforcer/mirror/integration/tests)
4. **实现**: 编码 + 单测
5. **验证**: 对持仓 15 标的跑一遍, 对比启用前后的结论明确度

## 2. S2 — timesfm 时序预测头

### 2.1 现状
- 主系统 `lgb_tscv_trainer.py` 用 LightGBM 时序交叉验证训练
- 缺口: 长序列(>2048)零样本预测 + 分位区间, LightGBM 需大量特征工程
- timesfm 2.5: 200M 参数, 16k 上下文, 连续分位 horizon 1k, LoRA 微调, 零样本

### 2.2 集成设计
- 新增 `utils/timesfm_predictor.py` (~250行)
  - `preflight_check()` — RAM/GPU/磁盘预检 (SKILL.md 强制要求)
  - `forecast(series, horizon, quantiles) -> {point, p10, p50, p90}`
  - `forecast_with_covariates(series, xreg)` — XReg 协变量
- 在 `lgb_tscv_trainer.py` 增加 `--predictor=timesfm|lightgbm|hybrid` 选项
- hybrid 模式: timesfm 出零样本基线 + 分位区间, LightGBM 出残差修正
- 模型缓存: `models/timesfm/` (800MB checkpoint)

### 2.3 阶段任务
1. **spec-requirement**: 适用场景 (日线/分钟线/因子值) + horizon 需求 + 与 LightGBM 的融合策略
2. **spec-design**: `timesfm_predictor.py` 接口 + hybrid 融合公式 + 预检降级路径
3. **spec-task**: 安装/预检/forecast/covariate/hybrid/integration/tests
4. **实现**: `pip install timesfm[torch]` → 编码 → 单测 (mock 模型)
5. **验证**: 对 15 标的 2024-2026 回测, 对比 LightGBM-only vs hybrid 的 Sharpe/最大回撤

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| timesfm 800MB checkpoint + GPU 依赖 | 预检降级到 LightGBM, hybrid 模式可选 |
| ai-berkshire 四大师 prompt 与 A股语境不符 | 适配 A股语境, 段永平/李录保留, 巴菲特/芒格本地化 |
| SkillSpector 扫描 1031 skill 耗时 | 增量扫描 + 基线缓存, 全量扫描离线跑 |
| S1 源码 clone 网络受限 | 最后执行, 失败则降级为"参考设计自研新闻模块" |
| 集成膨胀违反 YAGNI | 每子项先 spec-requirement 确认真实需求, 不提前构建 |
