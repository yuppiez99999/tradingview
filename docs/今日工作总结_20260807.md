### 4.2 修复的 3 个 tdam_client 真实缺陷（"假成功"类静默失败）
| 缺陷 | 影响 | 修复 |
|------|------|------|
| 响应解析只查 HTTP 状态码、忽略 body.code | 业务错误(42203/50001/40001)在 HTTP200 body → 误判成功、数据未写入 | 解析 body.code，非 0 抛 TDAMAPIError |
| 缺 team_id/agent_id 环境变量配置 | 默认 `default` 不匹配系统生成的 `team-xxx`/`agt-xxx` → team/agent not found | 支持 TDAM_TEAM_ID/TDAM_AGENT_ID |
| search_memory 对 conversation 漏传 agent_id | L0-L3 严格 isolation 查不到已写入的对话 | conversation/chat_memory/atomic 补传 agent_id |

### 4.3 关键经验
- TDAM 业务错误在 HTTP200 的 body.code——客户端必须解析 body.code，否则"假成功"静默失败
- skill 是 agent-scoped：须先用 `/v3/meta/agent/create` 创建 agent（`x-tdai-user-key` header 非 Bearer）
- conversation 自动登记 agent，但 skill 要求 agent 预存在
- skill name 须与 frontmatter.name 一致（40001），且全局唯一（42201）
