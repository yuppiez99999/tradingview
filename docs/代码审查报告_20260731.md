## 三、架构与设计问题

### 3.1 God Class / God Function — `daily_workflow.py`

- **规模**：9,082 行，仅 3 个类（`CircuitLevel` / `WorkflowConfig` / `DailyWorkflow`），其中 `DailyWorkflow` 含 **110 个方法**。
- **影响**：
  - 单个文件承载盘前、盘中、盘后全部逻辑，任何修改都需要理解 9k 行上下文。
  - 方法间隐式共享状态（如 `self.dry_run`、`self.ks`、`self._ks_armed`），难以单元测试。
  - 已有 `phase_signal` 方法内部再拆出 `_apply_*` 十余个私有方法，但仍集中在同一类中。
- **建议**：
  - 按 Phase 拆分为独立模块：`phase_check.py`、`phase_risk.py`、`phase_hedge.py`、`phase_signal.py`、`phase_execute.py`、`phase_report.py`、`phase_autolearn.py`、`phase_shadow_monitor.py`。
  - 提取共享状态为 `WorkflowContext` 数据类，明确依赖注入。

### 3.2 路径与配置漂移

- `utils/hedge_execution_engine.py` 中 `REPORTS_DIR` / `TRADE_PLANS_DIR` 指向 `v8.3_institutional/`，但项目中同时存在 `v7.5_institutional/`、`v8.3_institutional/`、根目录脚本等多套路径。
- `risk_guard_integrator.py` 中 `REPORTS_DIR` 与 `DAILY_REPORT_DIR` 并存，且注释显示曾因路径错误导致回撤检查失效（v8.6.9 P0 FIX）。
- **建议**：统一由 `config_manager.py` 或 `system_config.json` 返回所有目录，禁止在各模块中硬编码 `Path(__file__).resolve().parent.parent / "v8.3_institutional" / ...`。

### 3.3 导入链与可选模块爆炸

- `daily_workflow.py` 顶部有 **15+ 个 try/except ImportError**，涵盖 EDB 期货、扫描器、校准模块、自主学习、UnifiedRiskCockpit、v10 风控、v10 策略、十五五阶段管理等。
- 每个模块都有 `XXX_READY = False` 标志，运行时动态探测。
- **影响**：导入阶段隐藏了依赖缺失问题，`ImportError` 被吞掉后继续执行，可能导致后续 `NameError` 或静默降级。
- **建议**：
  - 区分“硬依赖”与“软依赖”：风控/执行相关模块应为硬依赖，缺失时直接报错退出。
  - 软依赖模块统一使用 `importlib.metadata` 或 `utils.config_manager` 做显式特性开关。

## 五、安全与健壮性扫描

### 5.1 高风险模式汇总

| 模式 | 数量 | 涉及文件数 | 风险等级 | 说明 |
|------|------|------------|----------|------|
| `except Exception` | 3,341 | 913 | **中** | 过多宽异常捕获，可能隐藏关键错误 |
| `eval()` | 462 | 116 | **高** | 需审计是否用于动态表达式解析 |
| `exec()` | 27 | 22 | **高** | 需审计是否用于动态代码执行 |
| `pickle.load()` | 13 | 8 | **中** | ML 模型加载必需，需确保文件来源可信 |
| `subprocess(..., shell=True)` | 6 | 5 | **高** | 需审计命令拼接是否可控 |
| `os.system()` | 17 | 5 | **高** | 同 subprocess shell=True |
| `requests verify=False` | 35 | 19 | **中** | 禁用 TLS 校验，需确认是否为内网/测试 |

### 5.2 具体发现

#### 5.2.1 `eval()` 使用（462 处）
- 部分用于动态因子表达式解析（如 `multi_factor_signal.py`），属于业务必需。
- 但缺乏输入白名单/沙箱，若因子表达式来自外部输入（如配置文件、网络），存在注入风险。
- **建议**：对 `eval` 使用场景做白名单，或替换为 `asteval` / `numexpr` 等安全解析器。

#### 5.2.2 `subprocess` / `os.system`（23 处）
- 主要用于 Windows 任务计划注册脚本（`.ps1` / `.bat`）和 Ollama 启动。
- 部分命令拼接使用字符串格式化，若参数来自外部输入存在命令注入风险。
- **建议**：统一使用 `subprocess.run([...], shell=False, check=True)` 列表传参。

#### 5.2.3 `verify=False`（35 处）
- 部分为内网/测试环境使用，但缺乏按环境区分。
- **建议**：通过 `REQUESTS_VERIFY` 环境变量控制，生产环境强制 `True`。
