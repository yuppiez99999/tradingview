## 3. 方向一：TDAM（腾讯云 Agent 记忆中枢）对接 cairn 记忆层

### 可行性判定：**可行**（高收益、低改造、可回退；Python SDK 与写入 API 已可用）

### 3.1 架构对照
| TDAM 资产（4 类） | 8.4 现状 | 补强点 |
|---|---|---|
| Chat Memory（对话记忆，L0→L3 分层蒸馏） | cairn 仅文件系统 + 188KB LOG | 自动分层、去冗余 |
| Skill（技能资产化，含版本/触发边界/验证规则） | `skills/` 目录散落 | 统一治理、版本/ACL |
| LLM-Wiki（知识沉淀，BM25+向量+RRF 混合检索） | cairn 27 专题文档 | 混合检索、链式下钻 |
| Code-Graph（代码影响分析） | 无 | 改因子/策略前评估影响面 |

### 3.2 落地策略（四期，cairn 不替换、降级为可读镜像）
- **Phase 0 沙箱只读**：Docker 起 TDAM（`deploy/global-images/start-all.sh` 一键启动），只导入 cairn 文档 + LOG，**8.4 零改动**。TDAM 面板 `http://localhost:8125`。
- **Phase 1 读侧增强**：给估值/风险/宏观三专家加记忆检索（通过 MCP `/v3/tools/list|call`），不改写路径。
- **Phase 2 写侧迁移**：用官方 Python SDK（`tencentdb_agent_memory_sdk_python`）将决策日志改写 TDAM，cairn 变导出镜像，解决「cairn/second-brain 双份维护」。
- **Phase 3**：Skill 生命周期 + Code-Graph 影响分析（CodeGraph 当前优先支持公开 HTTPS 仓库，私有仓库需等 SSH 凭证支持完善）。

### 3.3 关键约束
- **数据不出网**：TDAM 标签含 `local-first`，Docker 自托管，对交易敏感逻辑是加分。唯一外部依赖是 `.env` 中的 LLM 参数（用于记忆蒸馏），可配置本地 Ollama 实现完全离线。
- **Python 集成**：8.4 是 Python 系统，TDAM 已提供官方 Python SDK（`tencentdb_agent_memory_sdk_python-0.1.0`）+ REST `/v3/tools/*` 双通道。SDK 覆盖写入，REST 适合只读检索。
- **LLM 参数配置**：TDAM 需要两组 LLM 参数（memory 组 + proxy 组），均可指向本地 Ollama（`http://localhost:11434/v1`），实现完全离线。

### 3.4 工作量
Phase 0-1：约 2-3 天；Phase 2-3：约 1-2 周（SDK 已可用，无需再等）。

## 4. 方向二：TradingAgents 六专家对接

### 可行性判定：**可行**（桥双端齐备，TA 已支持 Ollama，环境变量切换即可激活）

### 4.1 重大发现（决定了可行性前提）
8.4 **已集成 TradingAgents**，但处于「接了线、没通电」状态：
- 微服务 `28_bridge.py` 存在于 `E:\各种PY程序\TradingAgents\28_bridge.py`（9KB，完整实现），但需手动启动，默认端口 8490 未监听 → 调用静默降级本地六专家；
- `orchestrate_tradingagents(` 全树 0 外部调用 → 入口休眠，真实决策管线 `run_decision()` 未接它；
- 默认 `openai` + `gpt-5.5`，但 **TA 已原生支持 Ollama**（`cli/utils.py:364`），通过环境变量 `TRADINGAGENTS_LLM_PROVIDER=ollama` 即可切换，**无需改源码**。

→ 你当下决策**完全是六专家 + SignalFusion 在跑**，TradingAgents 不在回路。

### 4.2 架构同构对照
| 维度 | 8.4 六专家 | TradingAgents |
|---|---|---|
| 分析层 | Value/Momentum/Sentiment/Macro/Weather | Analyst Team：market/news/social/fundamentals 4 分析师 |
| 辩论 | ai_decision 辩论/共识 | Researcher Team：牛熊双方结构化辩论（`max_debate_rounds`） |
| 风险门禁 | Risk-veto 专家一票否决 | Risk Management 团队（`max_risk_discuss_rounds`） |
| 最终裁决 | SignalFusion 聚合 | Portfolio Manager |
| 决策日志反思 | cairn LOG.md（文件） | `state_summary`（结构化）+ memory_log（反思层） |
| 差异 | 更重实盘安全/本地推理 | 更重编排与决策日志反思 |

### 4.3 Gap 清单
- **G4 黑盒化**：当前把 TA 整条流水线压成 1 票，丢了牛熊辩论与 `state_summary`（5 个分析报告摘要）。
- **G5 A 股数据错配**：TA `data_vendors` 默认 `yfinance`（美股为主），虽 `benchmark_map` 已含 `.SS`/`.SZ`，但行情/基本面/新闻数据源需换 A 股源（akshare/东财/sina）。
- **G6 决策日志孤岛**：TA 日志（`memory_log_path`）未回写 cairn/second-brain/TDAM。
- **G7 辩论互鉴**：两边辩论机制未互相借鉴。

### 4.4 校验清单（Phase 0，7 步）
1. 设置环境变量：`TRADINGAGENTS_LLM_PROVIDER=ollama`、`TRADINGAGENTS_DEEP_THINK_LLM=qwen2.5:7b`、`TRADINGAGENTS_QUICK_THINK_LLM=qwen2.5:7b`、`OLLAMA_BASE_URL=http://localhost:11434/v1`。
2. 启动微服务：`py -3.11 E:\各种PY程序\TradingAgents\28_bridge.py --port 8490`。
3. `curl http://127.0.0.1:8490/health` 探活，确认 `tradingagents_available: true`。
4. 单标的 dry-run：`py -3.11 28_bridge.py --stock 600519.SH --date 2026-08-06`（非实盘）。
5. 确认返回 `source == 'tradingagents'`（非降级 `fallback_local`）。
6. 检查 `state_summary` 是否含 market_report/news_report/fundamentals_report 摘要。
7. 19 ETF 双跑对照（TA vs 六专家），仅记录不执行，比对信号一致性。

### 4.5 落地路线（全程 Shadow、不接实盘主信号）
- **Phase 0 激活**（1 天）：配 Ollama 环境变量 + 启微服 + 探活 + 单标的 dry-run。
- **Phase 1 Shadow 双跑**（1 周）：在 `run_decision()` 中加旁路调用 `orchestrate_tradingagents()`，TA 与六专家并行，比对信号一致性，仅记录不执行。
- **Phase 2 拆多视角投票**：改写 `orchestrate_tradingagents()` 的结果处理，把 `state_summary` 的 5 个报告（market/news/social/fundamentals/sentiment）拆成 5 个准专家视角喂入辩论/聚合（解决 G4）。
- **Phase 3 A 股适配器 + 日志回写**：为 TA 编写 A 股数据源适配器（akshare/东财替代 yfinance），TA 日志回写 cairn/TDAM（解决 G5/G6）。

### 4.6 工作量
Phase 0：约 1 天；Phase 1：1 周观测；Phase 2-3：约 1-2 周。
