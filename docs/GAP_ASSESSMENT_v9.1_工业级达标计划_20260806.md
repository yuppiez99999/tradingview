## 四、与原功能升级计划的关系

本 v9.1 计划与原 `自我升级计划完成进度及后续工程_20260806.md` 的关系:

**前置依赖**: 原2计划的 U7/F1/V1/W5 功能升级应在本 v9.1 Phase 1-3 完成后推进。理由: 没有可信的压力测试和成交回报驱动PnL, 自我进化的 Shadow 账户评估基于无效数据; 没有环境隔离, 因子发现 Loop 的研究代码污染生产路径。

- U8 (期权执行链): 标"未启动"但 `hedge_order_executor.py` 已于 08-06 创建验证 (5笔订单撮合, Beta 0.5186→0.3558)
- U9 (DriftShadowIntegrator): 标"CLI未传入current_predictions"但代码L778已有加载逻辑, 需重新验证是否已修复

**S1/S2 维持远期**: C++/Rust重写(S1)和PTP硬件时钟(S2)维持"远期储备", 当前阶段(日频+模拟撮合)Python延迟足够, 不启动。

## 七、结论

v9.0 工程地基修复已完成, 系统现在具备**可运行的测试体系和 CI 基础**。距工业级产品的剩余差距集中在 3 个维度:

1. **执行落地** (G1/G2/G4/G15): 真实券商下单未接线, 再平衡断链, 成交回报与PnL脱节 — 需 Phase 2 (1周)
2. **可信度** (G3/G8/G11/G13): 压力测试空持仓, 告警未接入生产, CVaR非MC — 需 Phase 1+4
3. **工程隔离** (G5/G6/G9): 研究/生产未隔离, mypy不达标, 数据管道物理分层缺 — 需 Phase 3+4

按 Phase 1→2→3 顺序推进, **预计 08-22 达到"工业级可实盘"中期标准, 09-05 达到全面标准**。届时系统将从"高级回测/纸面交易平台"升级为"可信赖的工业级量化生产系统"。
