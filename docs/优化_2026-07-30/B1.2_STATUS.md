## 一、问题背景

`daily_trade_executor.py` 与 `ms_strategy/scripts/daily_trade_executor.py` 两处本地实现了简陋的交易日判断：

```python
def is_trading_day(d: date) -> bool:
    """检查是否为A股交易日 (简易判断: 周一至周五)"""
    return d.weekday() < 5
```

**风险**：
- 不识别法定节假日（国庆/春节/元旦/劳动节），节假日仍会误判为交易日
- 交易指令会在节假日生成，导致下游无效执行

**已有方案**：项目内已有 `utils/trade_calendar.py::is_trading_day()` 实现，基于 akshare 动态拉取 A 股交易日历，本地 JSON 缓存，支持节假日识别与三层降级。但原签名仅接受 `Optional[str]`，与调用方传入的 `date` 对象不兼容。

---

## 二、修复方案

### 2.1 增强 `utils/trade_calendar.is_trading_day` 入参类型兼容性

原签名：`is_trading_day(date: Optional[str] = None) -> bool`

新签名：`is_trading_day(date: Union[str, date, datetime, None] = None) -> bool`

- 支持 `str` ('YYYY-MM-DD' / 'YYYYMMDD' / 'YYYY/MM/DD')
- 支持 `datetime.date` 对象
- 支持 `datetime.datetime` 对象
- 支持 `None`（默认今天）

**保持向后兼容**：所有原调用方（传字符串）行为不变。

### 2.2 删除两个 `daily_trade_executor.py` 副本的本地实现

- 根目录 `daily_trade_executor.py:87-89`：删除本地 `is_trading_day`，改为顶部 `from utils.trade_calendar import is_trading_day  # noqa: E402`
- `ms_strategy/scripts/daily_trade_executor.py:104-106`：同样删除本地实现并改为统一 import（额外添加 `sys.path.insert`，因该副本原无 sys.path 配置）
