## 一、问题背景

`MAX_DRAWDOWN_LIMIT` 在 7 处硬编码:
- 6 处 `0.15` (组合整体回撤上限)
- 1 处 `0.08` (量化中性策略专属)

散落在 `alpha_hedge_engine.py` / `research/` / `v8.3_institutional/` 等多个模块,修改时容易遗漏,导致回撤阈值不一致.

**风险**:
- 修改一处阈值而忘记同步其他处,导致不同模块对"最大回撤上限"的理解不一致
- 回测验收用 0.15, 但实盘风控用 0.12, 会产生回测-实盘偏差

---

## 二、修复方案

### 2.1 唯一事实源: `v8.3_institutional/config/risk_params.yaml`

```yaml
# 组合整体最大回撤上限 (生产标准)
max_drawdown_limit: 0.15

# 量化中性策略专属 (策略文档: 70万资金, 140万名义敞口, 更严格)
quant_neutral_max_drawdown: 0.08
```

### 2.2 统一访问层: `utils/risk_params.py`

提供 fail-safe 的 getter 函数,ConfigManager 不可用时回退到模块内兜底常量:

```python
from utils.risk_params import get_max_drawdown_limit, get_quant_neutral_max_drawdown

max_dd = get_max_drawdown_limit()              # 0.15
qn_dd = get_quant_neutral_max_drawdown()       # 0.08
```

**特性**:
- 合理性校验: 值必须在 [0.01, 0.50] 区间,越界回退到兜底
- fail-safe: yaml 缺失/格式错误/解析异常 均不崩溃,返回兜底常量
- 兜底常量与 yaml 保持同步: `_FALLBACK_MAX_DRAWDOWN_LIMIT = 0.15`
