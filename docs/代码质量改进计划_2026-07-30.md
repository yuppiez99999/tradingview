## 二、Architect 阶段：改进方案

### 2.1 方案设计原则

1. **安全第一**：不破坏现有功能，每步都可验证
2. **自动化优先**：能用工具自动修复的不手动改
3. **影响面最小**：按文件逐步推进，每批改完即验证
4. **分优先级**：P0 阻断性问题 → P1 可靠性 → P2 可维护性

### 2.2 改进策略

```mermaid
flowchart TD
    A[代码质量改进] --> B[P0: 修复语法错误]
    A --> C[P1: 清理未使用导入]
    A --> D[P2: 类型注解补充]
    A --> E[P2: docstring 补充]

    B --> B1[scripts/_verify_b13.py]
    B --> B2[legacy_analysis f-string]
    B --> B3[test_trade_calendar]
    B --> B4[risk_calculator.py]

    C --> C1[ruff --fix 自动修复]
    C --> C2[手动验证导入安全性]

    D --> D1[public API 优先]
    D --> D2[核心模块优先]

    E --> E1[核心模块 public 函数]
    E --> E2[数据类/配置类]

    style A fill:#c8e6c9,color:#1a5e20
    style B fill:#ffcdd2,color:#b71c1c
    style C fill:#bbdefb,color:#0d47a1
    style D fill:#fff3e0,color:#e65100
    style E fill:#f3e5f5,color:#7b1fa2
```

### 2.3 为什么选择此方案

- **ruff --fix 是安全的**：ruff 的 F401 自动修复经过广泛验证，不会破坏功能
- **P0 语法错误必须先修**：阻止其他工具运行（mypy/pylint/pytest）
- **类型注解价值高**：提升 IDE 体验和 mypy 检查能力
- **docstring 影响文档生成**：对量化系统 API 文档至关重要
