## 三、Bug 与问题清单（按优先级）

### P1-1【测试腐化·已复现】动态权重测试硬编码日期滑出评估窗口

- 位置: `tests/unit/test_g7_signal_fusion_boost.py::TestDynamicWeights::test_compute_dynamic_weights_with_history`
- 现象: 单独运行即失败，`weights = {'ml': 0.5, 'ai_hedge': 0.5}`（期望 ml=1.0）
- 根因: 测试写入 `evaluated_at='2026-08-02'` 硬编码日期；`utils/signal_fusion.py:173` 动态权重窗口 = `now - 30天` = 2026-08-03，**审计记录已滑出窗口** → 视为无历史 → 回落注册默认权重
- 定性: 项目记忆中"硬编码测试日期随日历失效"已知模式的又一实例（同类教训已发生 ≥3 次）
- 修复: 测试日期改为相对当前动态生成（`(datetime.now() - timedelta(days=1))`）

### P1-2【工程缺陷·已定位根因】顶层 `alpha` 命名冲突导致测试顺序污染

- 位置: `tests/test_audit_lookahead_minunit.py::test_missing_ohlcv_raises_keyerror`（全量运行失败，单独运行通过）
- 现象: `ModuleNotFoundError: No module named 'alpha.qlib_signal_adapter'`
- 根因链（两文件 `tests/unit/test_daily_workflow_unit.py + tests/test_audit_lookahead_minunit.py` 即可复现）:
  1. `utils/path_config.py::setup_sys_path()`（及 `utils/system_check.py:473`、`v8.3_institutional/generate_daily_trade_plan.py:314` 等处）把 **`utils/` 目录本身**插入 sys.path

  3. `v8.3_institutional/daily_workflow.py:50-52` 又把 `ms_strategy/src` 插入 path —— 谁先插入谁赢，导入顺序决定 `alpha` 解析到哪个包
- 定性: 系统性命名空间缺陷——两个同名顶层包 + 散布式 sys.path.insert，任何新代码顶层 `import alpha` 都可能命中错误包
