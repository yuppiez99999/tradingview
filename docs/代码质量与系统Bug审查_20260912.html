03 · 新发现

SC-15 · P1vol_regime_weighter：约束链现金缓冲破坏，输出总和可偏离 1 达 +30%

utils/alpha/vol_regime_weighter.py:659-733 · VolRegimeWeighter.enforce_constraints

问题链（四步互相放大）：

  • 步骤 2（现金下限 L692-699）：现金 < floor 时无条件抬到 floor——凭空注入权重，不做对应压缩；
  • 步骤 3（差额归现金 L701-708）：裁剪后 sum>1 的赤字 delta 全部塞给现金——现金可变负（如 -0.30），无下限保护；
  • 步骤 4（负值保护 L710-716）：现金归零后不再重新归一——总和 ≠ 1 直接输出；
  • 步骤 5（最终校验 L718-726）：只把 final_total 写进日志字符串，无断言、无告警、无修正。

数值例（CASH_OFFENSIVE regime，矩阵 ±20%，7 风格各 0.135 + 现金 0.05）：

  • 原始和 0.9448 → 抬现金后 1.3448 → 四个 0.27 风格裁到 0.30 后 ≈ 1.35 → delta = -0.35 → 现金 = 0.05 − 0.35 = -0.30 → 负值归零；
  • 最终输出：四个 0.30 + 周期 0.10 + 现金 0 = 总和 1.30（超发 30%），现金=0（违背 cash_floor=0.05），权益类 0.135→0.30（+122%）。全程零告警。
  • 常规情形同样失真：赤字不按比例分摊回风险资产而先冲现金——现金被无声挪用，最坏时现金缓冲完全消失。

影响：etf_option_hedge_rebalancer.py:98,305-313 真实接入（对冲调仓 regime 适应路径，启用即踩）；auto_trading_system.py:242,417-460 走 USE_VOL_REGIME_WEIGHTER feature flag（默认 False，当前无实盘影响）——开 flag 前必修。

修复建议：改单次收敛循环——①抬现金按比例压缩风险风格；②赤字从最高权重风格扣除（或按比例分摊），不得单冲现金；③负值归零后重跑整条约束链；④步骤 5 改告警+强制修正（回退安全等权+现金 floor）。

置信度：高（代码路径直接推演，多组数值复算一致）
