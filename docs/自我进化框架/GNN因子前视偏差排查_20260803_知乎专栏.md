## 二、背景:GNN 供应链因子是什么

传统选股因子(动量、估值、量价)假设股票之间相互独立 — 但现实是,产业链上下游是联动的。上游原材料涨价,中下游成本承压;下游需求爆发,上游产能跟涨。这就是 **Lead-Lag 效应**:邻居先动,个股滞后跟随。

GNN(图神经网络)的核心思路:把股票视为网络节点,用供应链关系构建边,让模型自动学习"邻居信息如何传导"。

我的系统分三层渐进:

```
Layer 1:静态边权重 → Lead-Lag 因子(验证"邻居信息有没有增量")
    ↓ Gate 1 通过?
Layer 2:GAT 图注意力网络 → 学习边权重(验证"学习 > 手工")
    ↓ Gate 2 通过?
Layer 3:因子正式入库 → S5-S7 全流程门禁
```

每一层都有门禁(Gate),不通过就回退 — 这套设计本身是对的。问题出在:**门禁的评估代码本身有 Bug,导致门禁在"放水"**。

## 三、转折:代码审查发现的 5 个 Bug

事情从一次例行代码审查开始。我新写了 GNN 供应链因子代码,想检查有没有潜在逻辑 Bug。结果一查就是 5 个,按严重度分级:

| Bug | 严重度 | 位置 | 一句话描述 |
|-----|--------|------|-----------|
| B1 | P0 | IC 计算 | 用今天的因子"预测"过去的收益(前视偏差) |
| B2 | P0 | 多空收益 | 因子窗口和收益窗口末端重叠(前视偏差) |
| B5 | P0 | GAT 注意力 | 掩码用乘 0 而非 -inf,注意力泄漏到无边邻居 |
| B3 | P1 | Gate 判定 | 两个不相交集合各自非空就判 PASS + 反向因子被误杀 |
| B4 | P1 | 夏普定义 | 算的是单期年化收益却叫"夏普",名实不符 |

3 个 P0(严重)+ 2 个 P1(中等)。其中 **B1 是最严重的** — 它会让所有因子评估结果失真,包括那个 +0.039 的 GAT 增益结论。

下面逐个拆解。

## 四、前视偏差:量化交易最隐蔽的陷阱(B1/B2)

### B1:用今天的因子预测过去的收益

**问题在哪**

IC(信息系数)衡量因子对未来收益的预测力。计算方法是:取因子值序列和未来收益序列,算 Spearman 秩相关。

我的代码逻辑是这样的:

```python
# 原代码(有前视偏差)
factor_values = compute_lead_lag_factors(price_data, graph)
# ↑ 这里的 factor_values 是用"整条历史序列的最新价"算出的单一常数
# 比如因子 = closes[-1] / closes[-60] - 1,用的是最后一天的收盘价

for end_idx in range(start, end):
    future_ret = closes[end_idx + horizon] / closes[end_idx] - 1
    ic = spearmanr(factor_values, future_ret)
    # ↑ 用"今天的因子值"和"历史窗口的未来收益"做相关
```

看出问题了吗?**因子值是 T 时刻(最新)算的常数,却拿去和 T 之前各个历史窗口的未来收益做相关**。这相当于:你站在 2026 年 8 月 3 日,用今天的因子值去"预测"2025 年 1 月的收益 — 而且因为因子值不变,IC 序列的波动只来自收益端,ICIR(信息比率的稳定性)完全不可信。

打个比方:你让一个学生在期末考试后再做练习题,然后用练习题成绩"预测"期末成绩 — 当然预测得准,因为你已经知道答案了。

**怎么修**

```python
# 修复后(无前视偏差)
for end_idx in range(start, end):
    # 每个窗口在 end_idx 时点,用 closes[:end_idx+1] 就地重算因子
    truncated = {sym: {"closes": c[:end_idx+1]} for sym, c in closes_map.items()}
    factor_t = compute_lead_lag_factors(truncated, graph)  # 只用截止 end_idx 的数据
    future_ret = closes[end_idx + horizon] / closes[end_idx] - 1
    ic = spearmanr(factor_t, future_ret)
    # 因子和收益严格时点对齐
```

核心原则:**因子计算时点 ≤ 收益起点**,因子和收益窗口零重叠。

**影响**

CHAIN_CONCENTRATION 这个因子,原评估 ICIR = 0.272,"三次稳定为正,最有希望通过门禁"。修复后 ICIR 塌到 **0.058** — 这就是前视偏差制造的"镜像":因子本身没预测力,是评估代码在帮它"作弊"。

### B2:因子窗口和收益窗口重叠

**问题在哪**

多空收益模拟中,因子值用 `closes[-1]/closes[-20]-1`(含最新价),收益用 `closes[-1]/closes[-21]-1`(也含最新价)。两者共享了 `closes[-1]` — 因子值包含了收益期末的信息,IC 自然偏高。

**怎么修**

改为期初 `entry = T - horizon` 时点算因子,预测 `[entry, T]` 整期收益。因子时点在收益窗口起点之前,严格不重叠。

这两个 P0 修完后,**所有之前的因子评估数字都不可信了** — 包括那个 +0.039 的 GAT 增益。

## 五、GAT 注意力泄漏:一个 -inf 的差距(B5)

### 问题在哪

GAT(图注意力网络)的核心是注意力权重:对每个节点的邻居,按学习到的权重聚合信息。无边邻居不应获得注意力。

原代码的掩码方式:

```python
# 原代码(有泄漏)
score = score * adj[:, :, None]  # 无边邻居分数乘 0
alpha = F.softmax(score, dim=1)  # softmax(0) 仍非零!
```

问题在于 `softmax(0) = e⁰ / Σ ≠ 0`。无边邻居的分数被乘 0 后,softmax 仍会给它一个非零的注意力权重 — 这就是**注意力泄漏**:GAT 在聚合信息时,偷偷把不该参与的无边邻居也算进来了。

这相当于:你在一个社交网络里,本应只听朋友的话,但因为掩码没做好,你把所有人的话都听了一点 — 当然"信息更丰富",但这不是真正的图注意力,是变相的全局平均池化。

**怎么修**

```python
# 修复后(无泄漏)
mask = (adj == 0).unsqueeze(-1)
score = score.masked_fill(mask, float("-inf"))  # 无边邻居分数设为 -inf
alpha = F.softmax(score, dim=1)  # softmax(-inf) = 0,严格不泄漏
alpha = torch.nan_to_num(alpha, nan=0.0)  # 孤立节点整行 -inf → NaN → 归零
```

`softmax(-inf) = e⁻⁰⁰ / Σ = 0` — 无边邻居注意力严格为 0。孤立节点(没有任何邻居)整行都是 -inf,softmax 产生 NaN,用 `nan_to_num` 归零。

**影响**

这个 Bug 是 +0.039 增益虚高的**主要来源**。GAT 的注意力泄漏到无边邻居后,相当于获得了全局信息(全局平均池化),当然比只看邻居的静态权重"信息更丰富" — 但这不是学习能力带来的优势,是**掩码没做好导致的作弊**。

## 六、Gate 判定 + 夏普定义:两个 P1 级逻辑错误(B3/B4)

### B3:Gate 判定逻辑漏洞

**问题在哪**

Gate1 门禁要求:增量 IC ≥ 0.01 **且** ICIR > 0.3 **且** 多空夏普 > 1.0。原代码把这三个条件拆成两个独立集合:

```python
# 原代码(逻辑漏洞)
strong = [因子满足 IC≥0.01 且 ICIR>0.3]
ls_pass = [因子满足 多空>1.0]
verdict = "PASS" if strong and ls_pass else "FAIL"
# ↑ 两个集合可以不相交!因子 A 满足 IC/ICIR 但多空差,因子 B 满足多空但 IC/ICIR 差
# 组合起来就误判 PASS
```

更严重的是:**反向因子(ICIR < 0)直接被 `ICIR > 0.3` 过滤掉**。但 A 股的动量反转因子恰恰是负 IC — 邻居 60 日涨多了,该股后续反向下跌。这种因子的 ICIR 是负的,但反向使用后 effICIR = |ICIR| 完全达标。

**怎么修**

```python
# 修复后
direction = -1 if icir < 0 else 1          # 按 ICIR 符号判定方向
eff_ic = direction * ic_mean               # 方向修正后的有效 IC
eff_icir = direction * icir                 # = |icir|
eff_ls = direction * ls_raw                 # 方向修正后的多空收益

# 单因子交集:同一因子须同时满足三条件
passers = [f for f in factors if eff_ic >= 0.01 and eff_icir > 0.3 and eff_ls > 1.0]
verdict = "PASS" if passers else "FAIL"
```

**影响**

CHAIN_MOM_60D(邻居 60 日动量反向因子)原 ICIR = -0.503,被 `ICIR > 0.3` 误杀。方向修正后 effICIR = 0.503 > 0.3 — **从误杀变为通过**,这是 Gate1 从 FAIL 改判 PASS 的关键。

### B4:夏普比率名实不符

**问题在哪**

原代码计算"多空夏普"的方式:

```python
# 原代码(名实不符)
ls_return = (long_ret - short_ret) * 252 / horizon  # 单期年化收益
return ls_return  # 却以"夏普>1.0"为阈值
```

这算的是**单期年化收益**,不是夏普比率。夏普比率需要 `mean / std` 结构,单期收益没有标准差 — 名实不符。而且单期噪声极大,阈值"1.0"对年化收益过于宽松(年化 100% 的多空收益都常见)。

**怎么修**

```python
# 修复后(真正的夏普)
ls_returns = []  # 多期非重叠滚动多空收益序列
for w in range(windows):
    # 每个窗口计算一期多空收益
    ls_returns.append(long_ret_w - short_ret_w)

# 年化夏普 = 均值/标准差 × sqrt(年内期数)
sharpe = mean(ls_returns) / std(ls_returns) * sqrt(252 / horizon)
```

## 七、证伪:+0.039 增益消失

B1-B5 全部修复后,我新建了 `gat_layer2_validation.py`,套用无偏框架重新验证 GAT Layer 2 的 +0.039 增益结论。

### 无偏验证设计

- **B1/B2**:每个时点 T 用 `closes[:T+1]` 就地重算特征和标签,训练时点严格 < 测试时点
- **B5**:复用修复后的 `masked_fill(-inf)` 掩码
- **B3**:方向修正 `effIC = direction × IC`,`effICIR = |ICIR|`
- **B4**:多期非重叠滚动多空序列 → 年化夏普
- **公平对比**:GAT 和静态因子都聚合邻居 20 日动量,唯一区别是边权重来源(学习 vs 手工)

### 两次验证结果

| 配置 | 测试时点 | GAT IC 均值 | 静态 IC 均值 | 原始增益 | 统计检验 |
|------|---------|------------|------------|---------|---------|
| 251 天/217 只/6 训练 | 3 | -0.3780 | -0.3844 | +0.0064 | t = 0.76, p > 0.50 |
| 501 天/197 只/12 训练 | 5 | -0.2377 | -0.2394 | +0.0017 | t = 0.15, p > 0.85 |

对比原结论 +0.039,差距 **6~23 倍**。t 值远低于显著水平(p > 0.5),**增益与零无异**。

### 增益方向都不稳

5 个测试点的增益序列:`[+0.0195, +0.0145, -0.0380, -0.0106, +0.0230]` — 3 正 2 负,没有系统性优势信号。

### 证伪根因

1. **B5 掩码泄漏**(主因):GAT 注意力泄漏到无边邻居,相当于全局平均池化,人为增强"信息聚合"能力
2. **B1/B2 前视偏差**:原 IC 评估不可信,IC 序列方差只来自收益波动,+0.039 是噪声叠加偏差的产物

### GAT 还有微弱优势吗?

修复后 GAT 在 effICIR(+0.04~0.05)和多空夏普(+0.5~1.1)上仍略优于静态。但拆解后发现:

| 指标 | GAT | 静态 | 差异 | 解读 |
|------|-----|------|------|------|
| IC 均值(effIC) | 0.2377 | 0.2394 | -0.0017 | GAT 信号更弱 |
| IC 标准差 | ≈0.194 | ≈0.200 | -0.006 | GAT 略稳定 |
| effICIR | 1.1953 | 1.1585 | +0.037 | 方差下降 > 均值下降 |

effICIR 的优势**全部来自 IC 方差略小,而非 IC 均值更大**。这是 softmax 的平滑特性 — 注意力权重倾向于更均匀分配,降低单时点波动但也稀释信号。这不是"学习能力",是"加权平均的平滑副产品"。任何更平滑的聚合方式(甚至等权)都可能获得类似的"稳定性优势"。

**结论**:GAT 作为独立因子,在绝对预测力上未稳健优于静态权重。按 Gate2 闸门"不满足则回退 Layer 1",执行回退。

## 九、几个工程上的反思

### 1. 前视偏差是量化研究里最隐蔽的陷阱

它不会让代码报错,不会让结果看起来不合理 — 相反,它会让结果看起来**太好**。你看到 +0.039 会兴奋,不会怀疑。直到你逐行审计代码,才发现因子值用的是未来信息。

**排查方法**:对每一个 IC 计算,问自己一个问题 — **"这个因子值在收益起点时点,真的能算出来吗?"** 如果不能,就是前视偏差。

### 2. 不可复现的结论不算结论

cairn 文档里记录的 +0.039,代码库里**没有对应的可运行验证脚本**。这是"口头结论" — 写在文档里,但没有代码支撑。B1-B5 修复后重测,结论直接反转。

**教训**:任何量化结论必须有可复现脚本支撑。结论 → 脚本 → 数据 → 结论,形成闭环。没有脚本的结论,本质是"我觉得",不是"我验证了"。

### 3. 有偏评估会制造"学习优势"镜像

这次最深刻的教训:B5 掩码泄漏 + B1/B2 前视偏差叠加,让 GAT 在有偏框架下看起来"优于静态"。修复偏差后,"优势"消失 — 说明此前的优势主要来自偏差,而非真实学习能力。

这给所有"学习类模型优于基线"的结论敲了警钟:**先确认评估框架无偏,再谈模型优劣**。否则你优化的不是模型,是偏差。

### 4. 证伪一个错误结论,比发布一个亮点更有价值

+0.039 如果没被证伪,我会继续投入精力优化 GAT(调超参、加深网络、加条件化注意力),在一个错误方向上越走越远。证伪后,我回退到 Layer 1,把 CHAIN_MOM_60D 推进入库 — 这才是真信号。

**量化研究最大的浪费不是找不到因子,是在假因子上浪费资源**。

### 5. 反向因子必须按方向修正后评估

A 股动量反转是主流效应 — 邻居 60 日涨多了,该股后续反向下跌。这种因子 IC 是负的,但反向使用后完全有效。如果 Gate 用 `ICIR > 0.3` 这种单向阈值,会系统性误杀所有反向因子。

**修复**:`direction = -1 if ICIR < 0 else 1`,`effICIR = |ICIR|`。简单一行代码,但把 CHAIN_MOM_60D 从"误杀"变成了"通过"。

## 十一、结语

这一天最大的收获不是"通过了 S5",而是**亲手证伪了自己的 +0.039 结论,然后从废墟里捡出了一个真信号**。

量化研究本质是一场**和自己的偏差作斗争**的过程。前视偏差、掩码泄漏、定义错误 — 这些 Bug 不会让代码崩溃,只会让结果"看起来太好"。而"看起来太好"恰恰是最危险的信号。

我维护一个原则:**当一个结论好得难以置信时,先别兴奋,先查代码**。这一次,+0.039 确实好得难以置信 — 然后它确实是假的。但正是因为证伪了它,我才把精力转向了真正有价值的 CHAIN_MOM_60D,而不是在一个错误方向上继续投入。

证伪不是失败,是**纠偏**。在量化研究里,纠偏比发现更重要。
