## 1. 严重度模型

| 级别 | 含义 | 能否带过门禁 | 处理时效 |
|---|---|---|---|
| 🔴 **P0 阻断** | 资金安全/实盘正确性/数据正确性缺陷；或门禁/CI 配置失效；或工作区未收敛 | 否（exit 1） | 立即 |
| 🟡 **P1 建议** | 静默数值污染、可观测性缺失、明显逻辑隐患、门禁健壮性 | 否（应拦） | 本周内 |
| 💭 **P2/P3 挑刺** | 风格、可读性、非资金路径瑕疵、存量债务 | 是 | 周期清理 |

**资金安全升格规则**：任何触及「交易日期 / 行情数据 / 资金计算 / 风控阈值 / 下单指令」的缺陷，一律升格 P0。

## 2. 量化系统专项审查清单（Q1–Q5，升格为硬门禁）

> 这些规则静态工具抓不到、只会静默腐蚀决策。审查每一笔涉数据代码逐条核对；并建议固化为 `tests/contract/` 下的行为契约测试。

- **Q1 相关系数/IC 必须 `np.isfinite` 守卫**：`np.corrcoef`/`spearmanr` 对常数序列返回 NaN 不报错。先判方差再算，结果非有限按 0。
- **Q2 除零路径必须守卫**：`a/b`、`np.divide`、任何 `mean/std/var` 分母，当可为 0 时必须 `if denom != 0` 或 `np.where(b != 0, a/b, 0)`。
- **Q3 分母类参数构造期必须校验 > 0**：优化器风险厌恶/收缩强度/置信度，显式 `if x <= 0: raise ValueError`（已落地于 `black_litterman_optimizer.py`，须保持）。
- **Q4 陈旧/缓存数据必须标记 stale 并降级质量分**：兜底数据命中时 `quality_score` 不得满分，打 warning，禁止当实时数据流通。
- **Q5 禁止裸 `except:`**：仅捕获具体异常类型；裸 `except`/宽泛 `except Exception` 会吞 `KeyboardInterrupt`/`SystemExit` 并掩盖真实错误。

**新增 Q6 · 门禁自完整性（2026-08-12 新增，对应 R1）**：CI 引用的所有 `scripts/*.py` 必须存在且可执行；新增被 CI 调用的脚本必须先落地文件再引用。由 `ci_integrity_check.py` 机检。
**新增 Q7 · 单一事实源（对应 R2）**：成交/持仓/fills 必须有唯一落盘真相源；禁止"只生成不执行"的订单（历史 rebalance/hedge 断链同源）。PR 描述须说明订单最终进入哪个执行器。

## 3. 通用审查核查点（lint 之外的逻辑层）

- 缓存读写：读缓存必须校验有效性（范围/格式/跨年/过期）+ 隔离坏缓存；写前校验上游合理。
- 边界：空序列 `max/min/argmax`、单元素、长度不匹配分支。
- 浮点金额比较：用 `math.isclose` 而非 `==`；累加型金额优先 `Decimal`（当前仅 1 处）。
- 可变默认参数：禁止 `def f(x=[])`。
- 未定义名/重定义：`F811/F821`（活跃代码已清零，仅在存档可见）。
- 密钥/凭证：禁止硬编码；缺失视为 P0 ERROR，但 pre-commit 用 `--skip-datasource` 不强制连源。
- **交易所后缀**：禁止硬编码 `.SH`；统一走 `_infer_suffix()`（已落地，保持）。

## 4. 五步审查工作流

1. **静态初筛**：ruff（真实缺陷规则集 F/E9/BLE001/T201）+ bandit + mypy，仅作线索。
2. **语义复核**：按 Q1–Q7 与通用核查点过关键路径；静态看不出的用行为测试验证。
3. **关键路径契约测试**：每个 P0 函数配至少 1 个"正确行为"断言（如 `is_trading_day('2026-10-01')==False`）。
4. **门禁卡点**：本地 pre-commit + CI 双重拦截；P0/P1 不得带过。**新增：CI 完整性门禁（Q6）拦截"引用不存在脚本"。**
5. **闭环归档**：缺陷入 Backlog，修复必带回归测试，批量入 `CODE_REVIEW_FIX_ROUNDx.md`。

## 6. 分支 / PR / 完成定义（DoD）

### 6.1 分支策略
`main` protected、禁 force push；分支从 main 切出，存活 ≤5 天；`feat/fix/refactor/hotfix` 四类。

### 6.2 PR 规范
| 变更行数 | 处置 |
|---|---|
| ≤200 | ✅ 理想 |
| 200–400 | ⚠️ 需说明 |
| >400 | 🔴 要求拆分（格式化/重命名除外） |

PR 描述四要素：改了什么 / 为什么 / 影响面（是否触 P0 交易路径）/ 怎么验证（策略变更必附回测对比）。**新增：涉及订单生成的 PR 须说明订单最终进入哪个执行器（Q7）。**

### 6.3 完成定义（DoD，强制）
- [ ] 工作区已收敛（未提交变更 ≤100，R2）→ **新增卡点**
- [ ] ruff/bandit/mypy 无新增 P0/P1 告警
- [ ] Q1–Q7 专项核对通过（含 Q6 CI 完整性、Q7 订单事实源）
- [ ] 触资金/数据/风控路径的，新增契约测试
- [ ] 修复类变更带回归测试（负向：构造触发条件 → 断言已修复）
- [ ] 本地 pre-commit 与 CI 均绿（**CI 指修复 R1 后的真实绿**）
- [ ] 缺陷记入 Backlog 或 FIX 批次

## 8. 审查强度分级与时效

| 变更触及 | 审查者 | 必须核对 |
|---|---|---|
| P0 交易路径 | 2 人（或 AI 审查 + 隔日本人复审） | 全部 🔴 + Q1–Q7 |

## 9. 紧急修复通道（hotfix）

触发：盘中系统故障影响下单 / 风控失效 / 数据错误致信号异常。
流程：hotfix 分支可跳非必要门禁（保留 ruff F 类）；合并后 24h 内补 PR 描述+测试+复盘；**每个 hotfix 必须回答"为什么常规流程没拦住它"**，答案转新检查项。

## 10. 度量与复盘

每周看板（`quality_snapshot.py`）跟踪：P0 print 数（递减）、`.exception()` 数（递增）、增量门禁拦截次数、CI 完整性（0 缺失）、hotfix 次数（>3/月 专项复盘）。
阶段复盘三问：门禁指标是否达成（未达成真实阻碍？）/ 有无绕过流程（为什么？）/ 哪些检查项从没抓到问题（删掉）。
