### 2.2 五类失败模式与修复策略

测试失败不是随机噪声，而是五类有结构的工程问题。把每一类的根因和修复策略沉淀下来，下次遇到能直接复用。

**模式 1：依赖缺失（196/242）** — `ModuleNotFoundError: No module named 'scipy'/'pydantic'/'joblib'/'torch'`。根因是开发环境未安装完整依赖，而源码里的降级逻辑 `try: import scipy; except ImportError: return []` 会把 ImportError 静默吞掉，让测试连锁失败。修复：`pip install scipy pydantic joblib ntplib pyarrow torch scikit-learn`。教训：**降级路径应 `logger.warning` 而非静默 return**，否则依赖缺失会被掩盖。

**模式 2：降级逻辑未实现** — 注释承诺了降级但代码直接 `return []`。比如 `calc_ic_series_from_history` 的 docstring 说"scipy 缺失时降级 Pearson"，但代码没做。修复：在 `utils/alpha_factor/base.py` 新增 `_spearman_numpy` + `_average_rank` 纯 numpy 实现。教训：**注释即契约**——docstring 承诺的降级行为必须实现，且语义要等价（Spearman = Pearson of ranks），而非近似降级。

**模式 3：单例跨测试污染（10 个）** — 单独跑测试文件 26 passed，全量跑 10 failed。根因：`LimitPoolProvider` 是单例（`__new__` + `_initialized`），全量测试中某文件先创建实例并污染状态，后续文件拿到不完整实例。修复：测试文件加 `@pytest.fixture(autouse=True)` 重置 `LimitPoolProvider._instance = None`。教训：**单例模式与 pytest 测试隔离不兼容**，单例类应提供 `reset()` 类方法。

**模式 4：API 重构后测试过时（22 个）** — 源码重构移除了 iFinD API（改用 Wind MCP/东财/新浪回退链），但测试仍引用旧 API。修复：旧 API 有意移除的 `@pytest.mark.skip` 跳过并注明重构原因；回退链断言更新为匹配新回退链。教训：**重构 PR 必须包含测试更新**，CI 门禁应拦截"测试引用不存在的符号"。

**模式 5：环境变化导致测试假设失效** — 测试硬编码了"依赖已安装"或"依赖未安装"假设，但环境变了。修复：用 `pytest.importorskip("torch")` 或条件断言 `if _TORCH_AVAILABLE: assert torch_backend else: assert numpy_backend`。教训：**测试不应硬编码环境假设**。
