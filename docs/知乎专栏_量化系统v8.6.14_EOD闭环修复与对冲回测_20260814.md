### 3.3 shadow feeder 失败根因定位

现象：26 个标的全返回 `(None, None)`，`coverage=0%`。数据源健康检查通过（Wind MCP / TDX / AKShare 均 OK），但 `provider.get_historical_data('600276.SH', period='1d')` 只返回 1 行（当日）。

根因链：

```
shadow_real_data_feeder._fetch_symbol_prices()
  → _get_historical_data_cached(symbol, period="1d")
    → MarketDataProvider.get_historical_data(symbol, period="1d")
      → _fetch_historical_data()
        → _try_wind_mcp_historical(symbol, "1d")     # P1 优先
          period_mapping["1d"] = 1                   # ← BUG: 只取 1 天
          wind_get_kline(windcode, days=1)
          → 返回 1 行（当日）
      → 返回 1 行 DataFrame
  → feeder 要求 len(df) >= 2（需前一日收盘算 daily_return）
  → 全部 26 标的失败 → (None, None)
```

对比：TDX / AKShare 的 `"1d"` 对应 252 天，Wind MCP 和 Sina HTTP 的 `"1d"` 却只取 1 天。Wind MCP 优先级 P1，先返回 1 行即短路，后续数据源不执行。

## 七、Bug 根因总结与工程经验

今日修复的 4 个 Bug 按发现难度排序：

| Bug | 根因 | 发现路径 | 修复难度 |
|---|---|---|---|
| 建仓计划文件缺失 | 根目录小文件清理误删 | FileNotFoundError 堆栈 | 低（git 恢复） |
| PYTHONUTF8 编码崩溃 | Python38 GBK .pth + UTF-8 模式冲突 | site.py UnicodeDecodeError 堆栈 | 中（需知 Python38 site.py 加载机制） |
| OPENBLAS access violation | 多线程内存布局冲突 | 0xC0000005 崩溃无堆栈 | 中（需设环境变量绕过） |
| **Wind MCP period_mapping** | `"1d": 1` 只取 1 天 | 数据源健康检查通过但 26 标的全空 → 逐层排查至 period_mapping | **高**（健康检查通过掩盖了数据量不足） |

Wind MCP period_mapping Bug 的工程教训：**数据源健康检查只验证连通性，不验证数据量**。Wind MCP 返回 1 行（当日）而非 252 行（一年），健康检查标记 OK，但下游 feeder 要求 `len(df) >= 2` 才能算 daily_return，导致 26 标的全失败。此类"健康但不足"的故障需在数据源层加最小行数校验，而非仅检查是否返回非空。
