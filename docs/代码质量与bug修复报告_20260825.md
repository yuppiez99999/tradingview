## 一、修复的真实 Bug（按严重度排序）

### BUG-1 [高] P2.3 验证脚本策略-结果错位
- **文件**: `scripts/run_p23_validation.py:198`
- **问题**: `run_validation()` 在样本不足时会 `continue` 跳过策略，导致返回的 `results` 列表比输入 `strategies` 短。原代码 `for v, (name, eq, _) in zip(results, strategies)` 按位置配对——一旦有策略被跳过，后续所有策略的年化/回撤/Sharpe 指标会**错配到错误的策略上**，直接污染诚实回测三件套（DSR/CPCV/Noise）的验证结论。
- **修复**: 改为按策略名对齐 `v_by_name = {v.name: v for v in results}`，跳过未验证的策略。

### BUG-2 [中] ingest_cairn 假成功计数
- **文件**: `utils/experience_rag.py:352-376`
- **问题**: `add_document` 是 Tier M 操作，在非交互环境（CI/定时任务）被拒绝时返回 `None`。原代码无条件 `count += 1`，导致日志报告"摄入完成 N 个文档"但实际一个都没写入。
- **修复**: 检查返回值，被拒绝时告警并停止摄入（提示可用 `AUTO_CONFIRM_TIER_M=1` 批量放行）。

### BUG-3 [中] EvalResult 失败分析数据丢失
- **文件**: `utils/eval_flywheel.py:245-256`
- **问题**: `analyze_failures()` 给 `result.metadata` 动态挂属性，但 `EvalResult` dataclass **没有声明该字段**，且 `to_dict()` 不包含它——Stage 4 的失败根因分析（metric_fail_counts）在落盘 JSON 中全部丢失，飞轮的"分析→改进"闭环断链。
- **修复**: 为 `EvalResult` 增加 `metadata: dict[str, Any]` 字段并纳入 `to_dict()`。

### BUG-4 [低] register(bump_version=False) KeyError
- **文件**: `utils/prompt_registry.py:183-187`
- **问题**: 对 `latest=0` 或版本被清空的记录调用 `register(..., bump_version=False)` 时，`rec.versions[str(rec.latest)]` 直接 KeyError。
- **修复**: 版本不存在时回退为新增版本。

### BUG-5 [低] chat_with_prompt 未使用变量
- **文件**: `utils/google_skills_adapter.py:97`
- **问题**: `rec = reg.get(prompt_name)` 赋值后从未使用（F841）；`assemble()` 内部会自行 `get(name)`，未注册时抛 KeyError 由 except 分支兜底，该行冗余。
- **修复**: 删除冗余赋值并补充说明注释。

### BUG-6 [低] Tier M 确认提示重复打印
- **文件**: `utils/tier_safety.py:117-118`
- **问题**: `confirm_yes_no` 先打印 `[Tier M] {description}` 再打印 `{prompt}`，而 prompt 本身以 description 为前缀——描述重复出现两遍。
- **修复**: 有 description 时只打印一次。

## 四、遗留观察项（未修改，建议后续处理）

1. **`utils/eval_flywheel.py` run_full_cycle 的 max_iterations 形同虚设**：循环体末尾无条件 `break`，飞轮实际只迭代一轮。当前行为是安全的（改进建议需人工应用后才值得重评），但与 docstring "迭代 max_iterations 次或全部通过"不符，建议要么实现自动应用改进重评，要么简化签名。
2. **`_score()` 中 `if ref else` 把 ref=0.0 当作缺失**：IC_IR 参考值为 0 时走 val-only 分支，语义略有偏差，影响极小。
3. **运行时声明不一致**：`ruff.toml` 多处注释声称 "py38 target"（UP007/UP045 忽略理由），但 `pyproject.toml` 声明 `requires-python >= 3.10`，实际 .venv 为 Python 3.14.4。全库约 139 处 PEP604 注解（`X | None`）在 Py<3.10 会直接 TypeError（如 `utils/logger.py:58` 的 `Optional[str | Path]` 混合写法）。**注意：本机系统 Python 是 3.8.9，若任何脚本/计划任务用系统 python 而非 .venv 运行会炸**，建议统一入口或清理 ruff.toml 中过时的 py38 注释。
4. **experience_rag 的 GLM5Embedder 维度声明与实际向量可能不一致**：LiteLLM/openai 返回的 embedding 维度取决于模型（如 embedding-3 是 1024/2048），`_dim` 仅是本地声明；若换模型而语料库已有旧维度向量，余弦相似度会因维度不匹配报错（`_cosine` 中 np.dot 形状不匹配）。建议 ingest 前校验维度一致性。
