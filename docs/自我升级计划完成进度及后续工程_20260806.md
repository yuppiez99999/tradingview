## 十、核心架构原则与约束

系统自我升级遵循以下核心原则（源自 `cairn/self-evolution-framework.md` 和 `docs/自我进化框架/PLAN_后续升级扩展.md`）：

Feature Flag 治理约束：所有启用动作均受 HC-1（默认 False）、HC-3（一键回滚）、HC-4（L3 人工审批）、HC-5（Kill Switch 冻结）硬约束。高风险动作需双签授权（如 V1 自动调仓 `apply_to_portfolio` 模式）。

不可变性原则：始终创建新对象，绝不原地修改。多小文件优于少大文件（典型 200-400 行，最大 800 行）。共享逻辑提取到共享函数（如 `ui/components/names.py` 一处维护全局生效）。

数据源优先级链：Wind 数据终端 (P0) → Wind MCP (P1) → TDX 通达信 (P2) → 免费数据源层 (P3) → 新浪财经 (P4) → 本地缓存 (P5) → 兜底预定义价格 (P6)。2026-08-03 已剔除 iFinD。降级原则：始终优雅降级，不因上层数据源不可用而崩溃。

回测可信度四道关卡：正交性检验、IC 稳定性、DSR 防御性夏普、经济逻辑支撑。因子发现 Loop Engineering 通过这四道关卡入库，复用 DSRValidator。

观察期出口标准：Shadow 样本 ≥20 条 + 无异常漂移事件 + DriftMonitor 告警可解释且可操作 + Kill Switch 无误触发 + Public/Private 分离性健康。当前样本 9 条，预计 08-20 达 15 条，触发延长至 08-27。
