## 3. 外部资源增量价值排序

### P0 — 高增量价值（建议立即接入）

#### 1. `open-code-review` 固化为 CI 门禁
- **现状**: 已用于 GLM-5.2 审查，产出 73 条缺陷，但未固化为 CI
- **增量**: 将 LLM 审查从"手动触发"变为"每 PR 自动触发 + 夜间全量"
- **接入方式**: 补全 `.github/workflows/ocr-review.yml` 缺失脚本 + 配置 GitHub Secrets
- **成本**: 低（已有配置基础）
- **预期收益**: LLM 审查自动化，每 PR 自动产出缺陷报告

#### 2. 修复 CI 6 个缺失脚本
- **现状**: `ci.yml` / `quality-gate.yml` / `tdd-guard.yml` 引用的 6 个脚本不存在
- **增量**: 让已有的完善 CI 配置实际生效
- **接入方式**: 创建缺失脚本或移除引用
- **成本**: 低
- **预期收益**: 所有质量门禁从"配置存在"变为"实际运行"

### P1 — 中等增量价值（建议近期接入）

#### 3. `.skills/addyosmani-code-review-and-quality`（五轴审查）
- **增量**: 347 行五轴审查框架（正确性/可维护性/性能/安全/测试），补充 Q1-Q7 的通用工程视角

- **与已有关系**: 互补（Q1-Q7 偏量化专项，五轴偏通用工程）
- **成本**: 低

#### 4. `.skills/code-refactor`（Fowler 43 条重构规则）

#### 5. `.skills/diagnosing-bugs`（6 阶段调试纪律）

## 6. 总结

**量化系统的代码质量体系已经非常成熟，外部资源（ECC / .skills / FinClaw）的增量价值有限。** 真正的瓶颈是：

1. **CI 未实际运行**（6 脚本缺失）— 已有的完善配置形同虚设
2. **工作区未收敛**（915 未提交）— 代码流失风险
3. **大文件未拆分**（6230 行）— 违反自定 800 行上限

**建议**: 优先修复 CI 和工作区问题（P0），而非引入更多外部工具。外部工具中仅 `open-code-review 固化` 和 `addyosmani 五轴审查 + code-refactor 规则库` 值得接入，其余可不接。
