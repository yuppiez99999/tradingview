### 六道卡点（G0–G5）

```
G0 分支纪律 ──► G1 提交前 ──► G2 提 PR 前 ──► G3 CI 门禁 ──► G4 人工审查 ──► G5 债务状态
   (开工)        (pre-commit)     (三维度)        (增量静态)      (分级清单)      (RED 熔断)
```

**G5 是本次最实质的升级**（v3 完全缺失）：债务等级退出码直接驱动开发行为——

| 退出码 | 等级 | 强制行为 |
|:---:|---|---|
| 0 | GREEN | 正常开发 |
| 1 | YELLOW | 正常开发，每周至少还 1 项债务 |
| 2 | **RED** | **冻结 `feat/*` 与 `refactor/*` 开工**，仅允许 `fix/*` + `hotfix/*` |

### 用法

```bash
# 日常检查（G0 + G5）
python scripts/review_gate.py

# 提 PR 前自查（追加 G2 三维度）
python scripts/review_gate.py --files <改动文件...>

# pre-commit 模式：RED 时按分支类型硬拦截
python scripts/review_gate.py --pre-commit
```

退出码：`0` PASS ｜ `1` P0 阻断 ｜ `2` 债务 RED 冻结 ｜ `3` 门禁自身异常（fail-close）

## 3. 三个值得注意的发现

**① 分支 `1` 不是意外，是有意为之** — `cairn/LOG.md` 08-29 条目显示该分支用于 `git push origin 1` 全量同步。已相应修正文档措辞：即便出于操作便利，也不符合回溯锚点要求，建议同步后归并回 `main` 并删除。

**② 443 处告警不是 443 个缺陷** — 剥离 `ruff.toml` 豁免后（`--isolated --select F,E9,B,SIM`，排除第三方）确有 443 处，但绝大多数是**有意豁免**：fail-safe 编排层的宽泛 except（BLE001）、CLI/UI 输出（T201）、金融数学大写命名如 `S`/`K`/`T`/`Δ`（N806/N803）。**清零 443 会破坏 fail-safe 设计**。正确做法是新增代码过增量门禁、存量按童子军规则渐进。

**③ 门禁脚本自己必须先过门禁** — `review_gate.py` 初版触发 38 项 ruff 告警。已按项目"完成三连"修至 ruff 0 告警 + black 合规 + 功能自举通过。这既是自查，也是对体系有效性的实证：门禁对谁都一样。
