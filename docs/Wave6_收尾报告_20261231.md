## 二、关键技术决策

### 2.1 事件驱动 vs 向量化回测语义对齐
- G15 采用 "next-event" 语义（T 信号 → T+1 bar.open 成交）
- vectorbt 采用 `signals.shift(1)` + `price=opens.values` 实现等价语义
- 实测偏差 0.000%，证明两引擎在简单策略上完全等价

### 2.2 A 股 T+1 模拟借鉴
- SimTradeLab 的 lot-based 持仓管理：每个 BUY 成交产生一个 `PositionLot`，记录买入日期
- T+1 强制：SELL 时仅可卖出 `acquisition_date < current_date` 的 lot
- FIFO 消费：按时间顺序消费 lots
- 与 `utils/market_rules.py` 的 20cm 标的识别逻辑整合

### 2.3 Walk-Forward 验证框架
- 训练窗口估计 hedge_ratio / lookback / holdings → 测试窗口评估 OOS Sharpe → 滑窗前进
- OOS PnL 计算：`ret_A - hedge_ratio * ret_B`（两腿日收益率差，避免价差除零问题）
- 配对交易 OOS Sharpe 目标 ≥1.0（合成数据未达标，实盘需真实 A 股数据）

### 2.4 三层验证引擎（WFO→VEC→BT）
- WFO：训练窗口网格搜索最优 (lookback, holdings) → 测试窗口评估 OOS Sharpe
- VEC：多数票选稳健参数 + 统计 Sharpe 均值/标准差
- BT：用稳健参数跑完整回测，输出可审计报告
- 观察：VEC 平均 OOS Sharpe (0.1209) 远低于 BT 完整周期 Sharpe (2.2864)，提示单窗口 OOS 不稳定

## 三、W6.4.5 借鉴评估结论

### 3.1 quantitative_analysis 因子表达式引擎
- **机制**：基于 Python `ast` 模块的 AST 解析器（不使用 eval，安全性高）
- **白名单**：9 个 OHLCV 字段 + 5 个 series 方法 + 5 个 window 方法 + 6 个二元运算 + abs 函数
- **结论**：值得移植（有条件，优先级中）
- **移植路径**：`utils/alpha_factor/expression_engine.py`（独立模块，不侵入现有因子库）
- **扩展方向**：加截面算子（rank/zscore）+ 条件表达式（where）+ 与 `@register_factor` 整合

### 3.2 stock(myhhub) 筹码分布算法
- **机制**：基于成交量 + 价格区间估算每日筹码分布（150 档三角分布 + 换手衰减 + 一字板处理）
- **输出指标**：获利盘比例 / 平均成本 / 90-70 成本区间 / 集中度 / 筹码峰直方图
- **结论**：值得集成（推荐，优先级中）
- **移植路径**：`utils/alpha_factor/chip_distribution.py`（新增第 12 大类"筹码分布"）
- **衍生 Alpha 因子**：CYQ_PROFIT_RATIO / CYQ_CONCENTRATION / CYQ_COST_DEVIATION / CYQ_PEAK_POSITION

### 3.3 形态识别
- **结论**：暂不移植（优先级低，依赖 talib，本项目未集成 talib）

## 五、教训沉淀

1. **vectorbt 1.0.0 兼容性**：`price="open"` 字符串选择器触发 numba TypingError → 改为 `price=opens.values` 传数组
2. **OOS PnL 计算陷阱**：价差百分比变化在价差接近零时产生极端值 → 改用收益率差 `ret_A - hedge_ratio * ret_B`
3. **合成数据局限**：Walk-Forward / 三层验证在合成数据上 OOS 指标不稳定，实盘需真实 A 股数据评估稳健性
4. **评估任务边界**：W6.4.5 是评估而非实施，结论沉淀供后续 Sprint 候选，避免范围蔓延
