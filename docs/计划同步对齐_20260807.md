### 4.2 发现并修复的 3 个 tdam_client 真实缺陷（"假成功"类静默失败）
| 缺陷 | 位置 | 影响 | 修复 |
|------|------|------|------|
| **响应解析只查 HTTP 状态码、忽略 body.code** | `_call_with_circuit_breaker` | TDAM 业务错误(42203/50001/40001)在 HTTP 200 的 body.code 中，被误判为成功 → 导入"假成功"、数据实际未写入 | 增加 body.code 非 0 检查，抛 `TDAMAPIError` |
| **缺 team_id/agent_id 环境变量配置** | `TDAMConfig.__post_init__` | TDAM team/agent 用系统生成的带前缀 id(`team-xxx`/`agt-xxx`)，默认 `default` 不匹配 → skill 写入报 team/agent not found | 支持 `TDAM_TEAM_ID`/`TDAM_AGENT_ID` 环境变量 |
| **search_memory 对 conversation/chat_memory 漏传 agent_id** | `search_memory` | L0-L3 严格 isolation 模式缺 agent_id → 查不到已写入的对话记忆 | conversation/chat_memory/atomic 类型补传 agent_id |

### 4.3 关键教训（对齐系统文档"静默失败"主题）
- **TDAM 业务错误在 HTTP 200 的 body.code 中**，客户端必须解析 body.code 而非仅 HTTP 状态码，否则会"假成功"掩盖真实失败——这正是系统反复强调要杜绝的静默失败模式。
- **skill 是 agent-scoped**：必须先用 `/v3/meta/agent/create` 创建 agent（需 `x-tdai-user-key` header，非 `Authorization: Bearer`），绑定真实 team_id/agent_id 后 skill 才能写入。
- **conversation 自动登记 agent**，但 skill 要求 agent 预存在。
- **TDAM skill name 必须与 content 的 frontmatter.name 一致**（否则 40001 INVALID_FRONTMATTER），且 name 全局唯一（否则 42201 SKILL_NAME_DUPLICATE）。
