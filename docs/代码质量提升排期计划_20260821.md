## 2. 三个 Sprint 详细排期

### Sprint QC-1：P0 落地执行（2026-08-22 ~ 09-05，~2 周）

**目标**: 让已有的完善 CI 配置实际生效 + ocr 固化 + 工作区收敛

| 任务 ID | 任务 | 交付物 | 验收标准 | 预估工期 | 依赖 |
|---------|------|--------|----------|----------|------|
| QC-1.1 | 修复 CI 6 个缺失脚本 | 缺失脚本创建或引用移除 | `ci.yml` / `quality-gate.yml` / `tdd-guard.yml` 全部实际运行，CI 绿 | 2 天 | 无 |
| QC-1.2 | open-code-review 固化为 CI 门禁 | `.github/workflows/ocr-review.yml` 补全 + GitHub Secrets 配置 | 每 PR 自动触发 ocr 审查 + 夜间全量 scan 归档到 `reports/ocr_reviews/` | 2 天 | QC-1.1 |
| QC-1.3 | 收敛工作区 915 个未提交文件 | 分类处理：提交/归档/删除 | `git status` 未跟踪文件 < 50（仅临时/缓存文件） | 3 天 | 无 |
| QC-1.4 | CI 实际运行验证 | 全量 CI 运行报告 | 7 个 workflow 全部实际运行，无缺失脚本错误 | 1 天 | QC-1.1 + QC-1.2 |

**Sprint QC-1 门禁**:
- ✅ CI 7 个 workflow 全部实际运行（无缺失脚本错误）
- ✅ ocr 每 PR 自动触发
- ✅ `git status` 未跟踪文件 < 50
- ✅ 所有改动零行为变更（CI 修复除外）

**风险与缓解**:
| 风险 | 缓解措施 |
|------|----------|
| CI 修复可能暴露大量既有违规 | 分阶段启用：先 warn 后 error |
| ocr LLM 成本超预算 | 设置月度预算上限告警 + 仅审查 PR 改动文件 |
| 工作区收敛误删文件 | 先归档到 `_archive/` 再删除，保留 30 天回退窗口 |

## 3. 关键路径与依赖

```
QC-1.1 CI修复 → QC-1.2 ocr固化 → QC-1.4 CI验证
                                    ↓
QC-1.3 工作区收敛                    QC-2.1 daily_workflow拆分 → QC-3.2 覆盖率
                                    ↓
                                    QC-2.2 mypy strict → QC-3.1 ruff清零
                                    ↓
QC-2.3/2.4/2.5 外部接入（独立）      QC-3.3 全量验收
```

**关键依赖**:
1. **QC-1.1 CI 修复** 是所有后续任务的前置 — CI 不生效则所有质量门禁形同虚设
2. **QC-2.1 daily_workflow 拆分** 是 QC-3.2 覆盖率提升的前置 — 拆分后才好逐模块补测试
3. **QC-2.2 mypy strict** 是 QC-3.1 ruff 清零的前置 — 类型修复后 ruff 修复更安全

## 8. 铁律重申

1. **零行为变更**: 所有改动（除明确的 CI 修复外）不得改变现有行为
2. **CI 先行**: QC-1.1 是所有后续任务的前置，不修好 CI 不做其他

5. **每个 Sprint 独立验收**: 通过门禁后再进下一 Sprint
