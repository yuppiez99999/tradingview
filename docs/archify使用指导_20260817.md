# Archify 使用指导

> 生成时间：2026-08-17
> Archify 版本：v2.14（skill: `tt-a1i/archify`）
> 安装位置：`~\.agents\skills\archify`

## 一、定位

Archify 将小型 JSON 规范转换为**自包含交互式 HTML 架构图**（内联 SVG），支持深色/浅色主题、pan-zoom、搜索聚焦、路径追踪、导出（PNG/JPEG/WebP/SVG/WebM）。静态输出为默认，动画仅按需启用。

## 二、五种图类型

| 类型 | 适用场景 |
|---|---|
| `architecture` | 组件、服务、云/安全边界、基础设施拓扑 |
| `workflow` | 流程、审批门、工具调用、runbook、CI/CD |
| `sequence` | API 调用链、请求生命周期、异步追踪、返回 |
| `dataflow` | 数据管线、ETL/ELT、数据血缘、消费者 |
| `lifecycle` | 状态/状态机转换、重试、等待与终态 |

类型不确定时：

```bash
node bin/archify.mjs guide "场景描述" --json
```

## 三、核心命令

> 所有命令的 workdir：`~\.agents\skills\archify`

### 3.1 验证（修复阶段反复使用）

```bash
node bin/archify.mjs validate <type> <input.json> --quality showcase --json
```

- showcase 通过 = 9 项 artifact check 全绿 + 0 composition errors + 0 warnings
- 4 项 check 仅属基础验证，**不代表 showcase 通过**

### 3.2 交付（最终一次性，冻结规范 + 生成 HTML）

```bash
node bin/archify.mjs deliver <type> <input.json> <output.html> --quality showcase --json
```

- 交付会冻结规范字节为同目录私有快照，渲染并检查该快照，原子提交 HTML
- 返回规范与产物的 SHA-256 + 字节数
- **规范冻结后不再编辑**

### 3.3 视觉检查（交付后，不修改 HTML）

```bash
node bin/archify.mjs visual-check <output.html> --json
```

- 在 1440×900、1600×1000、1920×1080、2048×1320 四个尺寸测量容器
- 在最小和最大尺寸捕获 light/dark 截图，写入 contact sheet + JSON sidecar
- `visualReview` 始终为 `"pending"`：截图是检查证据，**不是自动 polish 声明**
- exit 0 = 容器+捕获通过，1 = 溢出或捕获失败，2 = Chrome 不可用

### 3.4 预览（开发循环，可选）

```bash
node bin/archify.mjs preview <type> <input.json> <output.html> --quality showcase
```

加 `--open` 仅在需要立即本地预览时使用。**默认不启动预览。**

### 3.5 自检与示例

```bash
node bin/archify.mjs doctor                    # 环境自检
node bin/archify.mjs demo <output-directory>   # 生成示例
```

## 四、标准工作流

```
1. 选类型（architecture/workflow/sequence/dataflow/lifecycle）
2. 读 schemas/<type>.schema.json + schemas/common.schema.json + examples/ 中一个匹配示例
   （仅读这些文件，用示例了解字段形状，不抄事实）
3. 写候选 JSON（新稳定 ID、领域措辞、布局；主路径清晰，≤12 主节点）
   - meta.quality_profile 设为 "showcase"
   - 默认省略 visual_preset（→ classic）、subtitle、legend（→ auto）
4. validate 循环修复（每轮只改诊断指出的字段，验证后立即交付前再验一次）
5. deliver 一次性交付
6. visual-check 收集桌面证据
```

## 五、JSON 规范关键字段

### 5.1 meta

| 字段 | 说明 |
|---|---|
| `title` | 必填，图标题 |
| `quality_profile` | `"showcase"` 或 `"standard"` |
| `viewBox` | `[宽, 高]`，宽 ≥ 320，高 ≥ 240 |
| `repository` | `{url, revision}`，声明 sources 时必填 |
| `views` | guided views，最多 5 章 |
| `visual_preset` | 默认省略 → `classic`；可选 `signal-flow`/`blueprint`/`editorial` |
| `animation` | `"trace"` 为可选动画；默认无 |
| `engineering_profile` | `"deployment-ownership"`，默认省略 |

### 5.2 components

- `type`：`frontend`/`backend`/`database`/`cloud`/`security`/`messagebus`/`external`
- `pos` + `size`：手动布局坐标
- `sources`：仓库证据路径（最多 3 个，需 `repository` + `--repo-root` 验证）

### 5.3 connections

| 字段 | 说明 |
|---|---|
| `variant` | `default`/`emphasis`/`security`/`dashed` |
| `fromSide`/`toSide` | `left`/`right`/`top`/`bottom`，方向契约 |
| `route` | `auto`/`straight`/`orthogonal-h`/`orthogonal-v` |
| `labelDy`/`labelAt` | 标签位置微调 |
| `via` | 中间拐点，诊断要求时才加 |

### 5.4 boundaries

- `kind`：`region` 或 `security-group`
- `wraps`：包裹的组件 ID 数组

### 5.5 cards

底部结论卡片，`dot` 颜色：`cyan`/`emerald`/`violet`/`amber`/`rose`/`orange`/`slate`

## 六、Mermaid 输入

直接粘贴 Mermaid 源码，archify 读取拓扑后**重新生成 JSON**（非机械转换样式）：

- `flowchart`/`graph` → `workflow` 或 `architecture`
- `sequenceDiagram` → `sequence`（participants → 语义参与者，arrows → messages）
- `stateDiagram` → `lifecycle`（状态与转换保留语义）

## 七、仓库证据

当图需反映真实代码时，在 component 中加 `sources`：

```json
{
  "id": "trainer",
  "type": "backend",
  "label": "LightGBM 训练",
  "sources": [
    { "path": "lgb_trainer/trainer.py", "label": "训练核心" }
  ]
}
```

需同时：
1. `meta.repository` 填入 `{url, revision}`（40 位 commit hash）
2. validate/deliver 加 `--repo-root <本地仓库路径>`
3. path 必须在仓库内、非目录、非 `.git`

## 八、常见修复模式

| 诊断 | 修复 |
|---|---|
| boundary 超出 viewBox | 增大 viewBox 或给边缘组件加 margin |
| label overlaps component | 设 `labelDy`（正数下移）或 `labelAt` |
| endpoint-side-direction | 垂直连接设 `fromSide:"bottom", toSide:"top"`；水平设 `left`/`right` |
| container-border-run | 调整组件位置让边界间留间隙，或用 `via` 拐点 |
| orthogonal-arrows 失败 | `route:"straight"` 产生斜线时改为 `orthogonal-v`/`orthogonal-h` 或默认 auto |
| path-escape / file-missing | sources 路径不含目录、`.git`；文件需在 git 中存在 |

## 九、语言与命名约定

- 读者可见字符串匹配用户请求语言（本项目用中文）
- 保留代码标识符、命令、协议、API 路径为英文
- `quality_profile` 默认 `"showcase"`；仅在用户明确要求密集图时用 `"standard"`

## 十、交付后注意

- **不要**在交付后编辑规范（已冻结）
- **不要**用 `overflow:hidden`、裁剪内容、内部滚动条、拉伸 SVG 伪造通过
- **不要**对非零 exit 声称成功
- visual-check 的截图是人工检查证据，`visualReview: "pending"` 不代表自动 polish 完成
