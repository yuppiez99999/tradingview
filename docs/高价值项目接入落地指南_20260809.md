## 3. 逐项落地方案

### 3.1 qlib —— 深化（已部分集成，P1）
**目标**：从「只跑 XGBoost_Top40_Reg」升级为 qlib 完整 WorkFlow（训练 + 滚动回测 + 信号输出），并尝试 LightGBM / Transformer 等模型。

**接入点**：复用 `qlib_data_bridge.py` 与 `docs/金融工程闭环` 的 QlibDataLoader；把产物（信号）写回 `config/positions.json` 的 `qlib_signal/qlib_rank` 字段。

**改造步骤**：
1. 在 `.qlib_experiments/` 下新增 `workflow_top400_lightgbm.yaml`，定义 `dataset_handler: Alpha360`、`model: LightGBM`、`trainer: tasks`。
2. 用 `qlib` 的 `Rolling` 回测替换系统里手写的回测脚本，统一指标口径（IC / ICIR / 最大回撤）。
3. `qlib_data_bridge` 增加**增量更新**能力（目前 `last_qlib_update` 字段说明已在做，做成定时任务）。

**代码示例（qlib WorkFlow 骨架）**：
```python
import qlib
from qlib.workflow import R
from qlib.auto import AutoDataHandler  # 示意

qlib.init(provider_uri="./qlib_data/cn_data", region="cn")
# 复用 qlib_data_bridge 生成的 Alpha360 数据
with R.start(experiment_name="top400_lightgbm_v2"):
    R.run(config_path="./.qlib_experiments/workflow_top400_lightgbm.yaml")
    rec = R.get_recorder()
    ic = rec.get_metrics()["IC"]
```
**验证**：与现有 `XGBoost_Top40_Reg` 做同区间对照（IC/ICIR/回撤），shadow 比对信号排名，不替换线上。
**风险**：低（纯 Alpha 侧实验，不影响执行）。

### 3.2 vnpy —— 实盘执行替换（缺失，P0）
**目标**：用券商 CTP/API 程序化下单，替代 `pyautogui/pywinauto` 点击同花顺 GUI（脆弱、慢、怕界面变动）。

**接入点**：`AlphaHedgeEngine.__init__(account_id, broker=None, mode="sim")`。`self.broker` 即下单通道；`RiskControl` 的风控在 `_execute_order` 之前/之后生效，与 broker 无关——所以**新增一个 `VnpyBroker` 适配器即可，不动风控**。

**代码示例（适配器骨架）**：
```python
# brokers/vnpy_broker.py
from vnpy.event import EventEngine
from vnpy.trader.engine import MainEngine
from vnpy.gateway.ctp import CtpGateway

class VnpyBroker:
    def __init__(self, ctp_config: dict):
        self.event = EventEngine()
        self.main = MainEngine(event_engine=self.event)
        self.main.add_gateway(CtpGateway)
        self.main.connect("CTP", ctp_config)

    def submit_order(self, symbol, qty, side, price):
        # 转成 vnpy 的 OrderRequest，经 RiskControl 后提交
        ...

    def get_account(self): ...
    def get_positions(self): ...

# 在 alpha_hedge_engine.main() 中：
# broker = VnpyBroker(load_ctp_from_env())
# engine = AlphaHedgeEngine(account_id="YOUR_ACCOUNT", broker=broker, mode="live")
```
**验证**：
1. `mode="sim"` 用 vnpy 的 `SimGateway` 回放历史tick，核对成交与 `RiskControl` 行为。
2. **shadow 运行**：vnpy 与同花顺 GUI 并行（vnpy 只模拟不下单），对比两者信号/委托一致性 ≥ 99% 后再切。
**风险**：需券商 CTP/API 账号与穿透式认证；**保留 `pyautogui` GUI 作为 feature-flag 降级路径**，异常即回退。

### 3.3 duckdb —— 数据底座整合（缺失，P0 高ROI）
**目标**：把散落的 `positions.json`、`market_returns.json`、`returns_history.json`（各 ~200KB）及大量 `.bak_*` 收敛为可查询表，减少备份泛滥、加速分析。

**接入点**：作为 `data_provider` 的查询/缓存层；现有「读 JSON + pandas」调用逐步改为 duckdb 查询。

**代码示例**：
```python
import duckdb, pandas as pd
# 直接查 JSON（无需先 load 成 DataFrame）
df = duckdb.query(
    "SELECT symbol, qlib_signal, qlib_rank FROM 'config/positions.json'"
).df()
# 或落盘为单文件库，替代 .bak 丛林
con = duckdb.connect("analytics.duckdb")
con.execute("CREATE TABLE returns AS SELECT * FROM 'returns_history.json'")
con.execute("INSERT INTO returns SELECT * FROM read_json_auto('returns_history.json.bak_*')")
```
**验证**：duckdb 查询结果 ≡ 现 pandas 读取结果；`analytics.duckdb` 体积 < 原 JSON 总和；`.bak` 文件可逐步停产生。
**风险**：中（数据迁移）——采用**双写过渡**：新写既写 JSON 也写 duckdb，跑通后读路径切到 duckdb，再停 JSON 备份。

### 3.4 openbb + tushare —— 统一数据层（缺失，P1）

**接入点**：`data_provider`（`ModuleLoader.load("wind_data_provider")` 现有加载点）；新增 `providers/openbb_provider.py`。

**代码示例**：

from openbb import obb

df = obb.equity.price.historical(

# obb.api() 启动 FastAPI/MCP 后端，ai_coordinator 直接问 "600028 近一月涨跌"

**价值**：多源统一 + 加 tushare 高质量 A股 + 支持 MCP 被 Agent 调用；与你已有的 `openbb_tushare` 扩展思路一致。
**验证**：同一标的，openbb(akshare) 与现有 akshare 直连结果一致；MCP 端点被 `ai_coordinator` 成功调用。

### 3.5 transformers / finbert / snownlp —— 舆情情感信号（缺失，P1）
**目标**：给信号融合加「舆情情感」维度（28 系统本身暂无情感模块；你在 E: 其他目录有舆情分析，可复用）。

**接入点**：新建 `SentimentSignalProvider`，注册进 `strategy_registry` 或作为 `data_provider` 的一路信号源，融入 `docs/金融工程闭环` 的信号融合。

**代码示例**：
```python
from transformers import pipeline
finbert = pipeline("text-classification", model="ProsusAI/finbert")  # 财经情感
def get_sentiment(texts):
    return [r["score"] if r["label"]=="positive" else -r["score"] for r in finbert(texts)]
# 中文社媒用 snownlp
from snownlp import SnowNLP
cn_score = SnowNLP(weibo_text).sentiments  # 0~1
```
**验证**：情感打分与人工标注抽样一致率 ≥ 80%；作为新因子加入回测，看 IC 是否提升。
**风险**：低（只新增信号源，可灰度开启）。

### 3.6 langchain / autogen —— AI 决策编排增强（缺失，P2）
**目标**：把现有「单点 Ollama 调用」升级为「多 Agent 推理 + 工具调用」，例如「分析师 Agent 出信号 → 风控 Agent 把关 → 交易 Agent 下单」。

**接入点**：增强 `get_ai_coordinator()`（位于 `utils/ai_coordinator.py`）；保留 **ollama 作本地推理后端**，用 MCP `python-sdk` 把系统工具（行情/持仓/下单）暴露给 Agent。

**代码示例（langchain 多Agent骨架）**：
```python
from langchain.agents import AgentExecutor
# 分析师 / 风控 / 交易 三个 tool-using agent，共享 ollama 后端
analyst = build_agent(tools=[market_query, sentiment_query], llm=ollama_llm)
risk    = build_agent(tools=[position_query, risk_check], llm=ollama_llm)
trader  = build_agent(tools=[submit_order], llm=ollama_llm)
```
**验证**：在 sim 模式下跑完整「分析→风控→交易」链路，对比原单点决策的信号质量/胜率；shadow 不影响实盘。
**风险**：中（多 Agent 易失控）——用 `human-in-the-loop` + 现有 `kill_switch`/`fat_finger` 兜底。

### 3.7 freqtrade + ccxt —— 加密货币腿（缺失，P2）
**目标**：在纯 A股之外补 7×24 加密货币交易；ccxt 作底层行情/下单，freqtrade 作策略/回测框架。

**接入点**：作为**独立交易腿**，复用 `RiskControl` 与 `AlphaHedgeEngine` 的风控逻辑（抽出风控为可复用模块）；系统生成信号 → freqtrade 执行（信号消费模式，避免重复造轮子）。

**注意**：freqtrade 自带策略/回测，建议「**信号消费**」而非「重写策略」，降低维护成本。
**验证**：crypto 腿在 sim 跑 30 天，风控阈值与 A股腿一致；与 ccxt 直连行情对齐。

## 4. 分阶段排期（沿用你的工作流）

| 阶段 | 内容 | 周期建议 | 关键验证 |
|---|---|---|---|
| **Phase A（高ROI·低风险）** | duckdb 整合 → openbb/tushare 数据统一 → 情感信号 | 2~3 周 | 查询结果一致、备份数下降、新因子 IC 提升 |
| **Phase B（深化核心）** | qlib 完整 WorkFlow + 多模型 → langchain/autogen 决策增强 | 3~4 周 | 与现有 XGBoost/单点 Ollama 对照，shadow 比对 |
| **Phase C（高门槛·慎入）** | vnpy 实盘替换 → freqtrade 币圈腿 | 4+ 周 | sim 回放 + shadow 并行 ≥ 7 天，准确率 ≥ 99% 再切 |

每阶段遵循：**选型 → 回测 → 审指标 → 调优 → 定版 → 部署**；阶段间独立验收，避免多项目并行回归（见 §5）。

## 5. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| vnpy 需券商 CTP/API + 穿透认证 | 实盘不可用 | 保留同花顺 GUI 作为 feature-flag 降级 |
| duckdb 迁移数据丢失 | 分析中断 | 双写过渡，停 JSON 备份前校验一致性 |
| 多 Agent 决策失控 | 错误下单 | human-in-the-loop + 现有 `kill_switch`/`fat_finger` 兜底 |
| 多项目并行改代码 | 回归风险 | 分阶段、每阶段独立验收再进下一阶段 |
| freqtrade/ccxt 交易所 API 限频/封禁 | 信号延迟 | 仅作信号消费，限频与重试由 freqtrade 托管 |

**质量门禁**：改动须过既有 `.ruff` / `mypy` / `pre-commit`（`forbid-p0-risk`）+ `code-review-graph` MCP 复查；结论沉淀进 `cairn/` 知识专题文档。
