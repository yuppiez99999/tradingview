# 创世纪：用 AIDE² 自我进化智能体，构建和维护量化程序

> 专栏：创世纪——基于 AIDE² 的量化程序
> 本文回答一个核心问题：**当一个 AI 智能体具备"自我进化"能力后，用来做量化交易程序，会发生什么？**
> 这不是一篇讲"策略"的文章，而是一篇讲"**如何让 AI 智能体当你的量化研究员 + 程序员 + 风控审计师 + 知识管家**"的工程笔记。

---

## 引子：AIDE² 不是工具，是"会进化的同事"

传统开发流程里，AI 是"工具"：你给 prompt，它吐代码，你 review，它改。用完即忘，下一次从头再来。

**AIDE²（自我进化智能体）** 改变了这个关系。它的核心不是"生成代码"，而是**"像人一样在工作中持续成长"**：

- 它**有记忆**——做完的事、踩过的坑、沉淀的结论，不会随着对话结束而消失
- 它**会自我审查**——主动 review 自己写的东西，发现 bug 而不是等你指出
- 它**会沉淀经验**——把每次修复归纳成"防复发清单"，下次不再犯
- 它**会规划升级**——基于对系统现状的理解，主动提出下一步该做什么

而我做的这个量化程序，就是**把 AIDE² 这套"自我进化"的理念，完整落地到量化交易领域**的一次实践。

用一句话概括：**传统量化是"人写策略"，AIDE² 量化是"智能体维护策略"——它不只帮你写，还帮你盯着、修复、迭代、并记住一切。**

---

## 一、AIDE² 的自我进化能力，如何映射到量化系统

AIDE² 的自我进化，不是玄学，它由四个可落地的能力构成。我把它映射到量化系统的四个环节：

| AIDE² 能力 | 量化场景落地 | 对应系统模块 |
|:-----------|:-------------|:-------------|
| **长期记忆** | 把策略逻辑、踩坑记录、决策依据沉淀为知识库 | `cairn/` 知识库（LOG + 专题文档）|
| **自我审查** | 主动扫描代码，发现前视偏差、fail-open 熔断等 bug | open-code-review 全库审查 |
| **经验沉淀** | 把 bug 归纳为"防复发清单"，越用越强 | `code-review-lessons` 经验库 |
| **自我规划** | 基于现状主动制定升级路线 | 升级计划 + 路线图（ROADMAP）|

这四个能力，正好构成量化系统最需要的四件事：**策略要可追溯、代码要可信、经验要积累、系统要持续进化。**

## 二、AIDE² 如何"构建"量化系统 —— 四层架构

如果用 AIDE² 来搭建量化系统，它会把系统组织成四层，每层解决一类问题：

```
┌─────────────────────────────────────────────────────────────┐
│ E  Evolution  漂移检测 → 自动重训 → 影子账户 → 灰度发布        │
├─────────────────────────────────────────────────────────────┤
│ D  Discipline 三级熔断 / 止损纪律 / 成本模型 / fail-closed    │
├─────────────────────────────────────────────────────────────┤
│ I  Intelligence 数据治理 / 因子工厂 / ML 信号 / point-in-time │
├─────────────────────────────────────────────────────────────┤
│ A  AI Decision 多智能体投票 / LLM 决策 / 信号融合              │
└─────────────────────────────────────────────────────────────┘
```

四层之间是**有向数据流**：I 层向上供给 A 层做决策，A 层的决策向下交给 D 层执行，E 层在旁监控并回流反馈。这和 AIDE² 的工作方式同构——**感知 → 决策 → 执行 → 反思 → 记忆**。

### A 层：多智能体（Multi-Agent）决策

不是单个模型，而是一个**分析师智能体池**（20 个 Agent），每个承载一种独立推理框架（价值派 / 反身性派 / 尾部风险派 / 跨学科派）。Agent 之间解耦，只共享原始输入，避免群体思维。

信号融合用动态权重：
```
final_signal = Σ w_i · normalize(signal_i)
```
权重基于各源近期 IC/ICIR 滚动回归自适应调整，融合前做正交化。

### I 层：数据治理 —— 回测可信度的地基

这是 AIDE² 自我审查时**花力气最大**的部分，因为数据错了，上层全错。

**前视偏差（Lookahead Bias）**：在决策时点 T 用了 T 之后的信息。它不报错，反而让回测"看起来很好"。AIDE² 审查时识别出两种形态：

```python
# 形态1：财务快照未按决策日截断
fundamentals=fundamentals  # ❌ 用了含未来财报的完整快照
```
修复：point-in-time 按**实际披露日**对齐。A股披露规则有个反直觉的坑——**2026-04-01 时，2025 Q4 年报（次年 4/30 披露）和 2026 Q1 都不可用**，只能用到 2025 Q3。

```python
# 形态2：IC 用过去收益近似未来收益
ret = closes[-1] / closes[-lookback] - 1  # ❌ 自相关伪 IC
```
修复：必须用未来收益 `closes[-1]/closes[-1-forward]-1`。

### D 层：纪律执行 —— fail-closed

AIDE² 审查时发现最危险的一类 bug：回撤熔断**只打日志，不真正执行**——"你以为有保护，实际没有"。修复原则：风控返回的决策必须被调用方消费，失败时默认拒绝交易（fail-closed），绝不放行。

### E 层：自我进化 —— 策略生命周期

策略有生命周期：漂移检测 → 自动重训 → 影子账户验证 → 灰度发布 → 退役。每一步都有硬性闸门（绩效 vs 回测偏差 > 30% 拒绝上线）。

## 三、AIDE² 如何"维护"量化系统 —— 一次真实闭环

前面是"AIDE² 帮我建系统"。但 AIDE² 真正的价值，在**"帮我维护系统"**。我在本周刚完成了一次完整的 AIDE² 工作闭环，这比任何架构图都更能说明问题：

### 第 1 步：自我审查（open-code-review）
AIDE² 对全库做了一次资金关键路径审查（交易执行 / 风控对冲 / 回测数据管道 / 基础数据层），发现 **25 个真实问题**：
- 3 CRITICAL（回测前视偏差 ×2、fail-open 熔断）
- 9 HIGH（凭证泄露、过期合约、幸存者偏差、复权不一致……）

### 第 2 步：制定修复计划
按优先级分级：P0（回测可信度 + 资金安全，本周）→ P1 → P2 → LOW，每项都带验收标准和测试建议。

### 第 3 步：执行修复（15 项）
- 修复回测前视偏差（point-in-time 对齐）
- 堵住 fail-open 熔断（真正消费决策）
- 轮换泄露的 API Key
- 滚动过期的期货合约 + 增加到期校验
- 统一复权口径、加涨跌停/停牌约束、成交成本建模……

### 第 4 步：经验沉淀（关键！）
这是 AIDE² 与普通工具的本质区别——**它把这次修复归纳成了可复用的"防复发清单"**，写进知识库：
- 披露日 ≠ 报告期
- 4 位合约月份码是 YYMM 而非 YYYYMM
- 期权短码年份需 as_of 推断
- 复权口径同计算不混用
- ……

以后 AIDE² 再写这类代码，会直接对照清单，**不再犯同样的错**。

### 第 5 步：自我规划升级
基于对系统现状的理解，AIDE² 主动制定了后续升级路线（U1-U7）：完整时序 IC、涨跌停数据接入、复权因子、诚实回测三件套……

## 四、AIDE² 做量化的三个独特价值

### 1. 记忆 = 策略可追溯 + 经验不丢失
普通开发，每次对话都从零开始。AIDE² 有 `cairn/` 知识库（LOG + 专题文档），策略为什么这么设计、踩过什么坑、做了什么决策——全部可追溯。**团队交接、半年后复盘，都有据可查。**

### 2. 自我审查 = 主动发现 bug，而非等出事故
传统流程靠人 review。AIDE² 会主动审查自己的代码，重点盯**逻辑类 bug**（前视偏差、fail-open、幸存者偏差）——这些是静态工具（ruff/bandit）抓不到、但足以毁掉整个系统的东西。

### 3. 经验沉淀 = 越用越强
每次修复，都变成"防复发清单"。**AIDE² 不是每次从零开始，而是站在自己过去的肩膀上**——这正是"自我进化"的字面意思。

## 五、给想入门的朋友：三句技术流实话

### 1. AIDE² 的价值不在"能写代码"，在"能维护系统"
写代码只是起点。它真正厉害的是：**写完能自查、出 bug 能修、修完能记住、记住能迭代**。这才是"自我进化"。

### 2. 用 AIDE² 做量化，先设计"fail-closed"
风控的默认行为必须是"拒绝交易"，而不是"放行"。一个"永远不会让你亏到本金"的架构，才有资格谈收益。

### 3. 回测的意义是"证伪"，不是"证明"
看到漂亮的回测曲线，第一反应应该是："哪里前视了？哪里幸存者偏差了？"**好回测是用来暴露自欺欺人的，不是用来证明能赚钱的。**

**真正的"创世纪"，不是一次完成，而是让一个会进化的智能体，日复一日地把混沌推向秩序。**
