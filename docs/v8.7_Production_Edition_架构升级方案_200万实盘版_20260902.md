## 四、运营中心（两层架构）

### 4.1 设计原则

聚合引擎走报告侧（零侵入，兑现 Q4 提前决策）；Dashboard 只是聚合 JSON 的**只读消费者**（新增 Streamlit 页，不动现有页面、不接触生产链路）。引擎先落，展示层后挂，两层解耦。

### 4.2 聚合引擎层（Q4，零侵入）

- **入口**：`scripts/compute_health_score.py`，计划任务交易日 17:15（衔接 17:10 每日状态报告之后）
- **五维遥测 → 加权评分（0-100）**：

| 维度 | 数据源（全部既有） | 示例指标 |
| --- | --- | --- |
| 模型 | 因子评估产物 / drift 监控 | IC、ICIR、漂移状态 |
| 数据 | `reports/degradation_log.jsonl` | 当日降级条目数、数据源可用性 |
| 交易 | TCA 双引擎 / FillsStore | 成交率、滑点、订单超时 |
| 风险 | VaR / regime / Greeks | VaR95 使用率、regime 状态、Delta/Gamma 敞口 |
| 资金 | 账户状态 / NAV 对账 | NAV 偏差、现金充足率 |

- **产出**：`reports/health_score/health_score_{date}.json`（五维分项 + 加权总分 + 异常标记）+ 摘要注入每日状态报告头部
- **降级语义**：某维数据不可得 → 该维按 60 分中性值 + `degraded_dimensions` 显式标记（fail-open，观测路径不阻断）
- **调度**：Windows 计划任务 `S12_DailyReport` 同族模式（重试 3 次/5 分钟，幂等覆盖）

### 4.3 Dashboard 展示层（Q4 末，12-10 冻结后）

- **实现**：`ui/pages/` 新增"生产运营中心"页（Streamlit，复用现有组件体系）
- **只读数据源**：聚合 JSON + 每日状态报告，不直连生产数据库
- **版面**：
  1. 总评分卡（当日成立 + 近 30 日趋势线 + 状态色 GREEN/YELLOW/RED）
  2. 五维雷达图 + 各维明细
  3. 关键指标集：NAV / Sharpe / Alpha（真实归因）/ IC / ICIR / 漂移 / 成交率 / 滑点 / VaR / CVaR / Beta / Delta / Gamma
  4. 异常时间线（degradation_log + 熔断/KillSwitch 事件）
  5. 灰度进度条（20 万 → 100 万 → 200 万阶段状态）

## 五、实盘 SOP（完整运营手册）

**落地物**：`docs/runbooks/PRODUCTION_OPERATIONS_RUNBOOK.md`（复用既有 runbooks 模式：HEDGE_ORDER_EXECUTOR / MODEL_DRIFT）

### 5.1 三段式日常流程

| 段 | 时间 | 检查单要点 |
| --- | --- | --- |
| 开市前 | 09:00-09:15 | ① 数据源四查（Wind/akshare/baostock/QMT 连通）② 计划任务昨夜执行状态（S12_Shadow_EOD / S12_DailyReport / 备份任务）③ 风控配置生效确认（`QUANT_STRICT_CONFIG` 无降级审计新增）④ 账户状态与隔夜持仓对账 |
| 盘中 | 持续 | ① 实时监控页巡视频率（30 分钟）② 异常处置走 §5.2 决策树 ③ L2 以上异常记当日运营日志 |
| 收盘后 | 15:30-17:30 | ① EOD 任务链执行确认 ② 每日状态报告 + Health Score 检视 ③ 真实归因核对（成本非零、无 degraded）④ 止损水位 / 备份落盘确认 |

### 5.2 异常分级响应表

| 级别 | 定义 | 响应动作 | 时限 |
| --- | --- | --- | --- |
| L1 观察项 | 单次数据降级、报告字段缺失 | 记录 + 当日修复 | 当日 |
| L2 功能降级 | 主数据源断开、TCA 缺数 | 切备用链路（Wind→akshare→sina）、暂停 Alpha 轮动 | 30 分钟 |
| L3 资金风险 | 回撤逼近预算、熔断触发、NAV 偏差 >1% | 减仓 / 暂停建仓（`day_capital_multiplier` 降档）、人工复核 | 立即 |
| L4 灾难 | KillSwitch 触发、主机故障、QMT 长时间断开 | 停止一切自动交易 → 走 §六恢复手册 → 人工对账 | 立即 |

### 5.3 附属模板

周报（周收益 / 归因摘要 / 异常汇总 / Health Score 均值）/ 月报（月度绩效 vs 回测分布带 / 风险预算使用率 / 灰度阶段评估）/ 单人岗位职责说明（决策角色 vs 执行角色分离原则：系统执行、人只做 L2+ 处置与双签）。

## 六、灾难恢复（RPO 1 天 / RTO 2 小时）

### 6.1 备份策略

- **时点**：每日 EOD 链完成后约 17:30，计划任务自动执行（重试 3 次/5 分钟）
- **内容**：账户状态（shadow/实盘）/ 止损水位（`stop_loss_water_marks.json`）/ degradation_log / 配置目录（config/）/ 交易记录（FillsStore）/ Health Score 历史
- **目的地**：①本地异盘（完整）②云端（关键小文件：账户状态 + 止损水位 + 配置，用于主机故障场景）
- **保留**：本地 90 天滚动 + 云端 30 天滚动

### 6.2 分场景恢复手册（SOP 附录）

| 场景 | 恢复步骤要点 | RTO |
| --- | --- | --- |
| 数据源故障 | 备用链切换（既有 fallback 链）+ 当日数据完整性校验 | <30 分钟 |
| 主机故障 | 裸机恢复：环境重建 → 云端关键状态回拉 → 计划任务重建 → 对账后恢复交易 | ≤2 小时 |
| QMT 故障 | T16 孤儿单检测 → 手动对账（成交 vs 委托）→ 恢复后重放未完成订单 | ≤1 小时 |

### 6.3 与 Chaos 演练对齐

Chaos 六场景（Wind 断开 / QMT 断开 / 数据错一天 / ETF 停牌 / 期权无法成交 / 模型输出异常）验收标准统一为：**fail-closed 进入安全状态 + 留审计 + 按恢复手册 2 小时内恢复至可交易状态**。备份恢复演练每季度 1 次（首次随 Q4 任务交付）。
