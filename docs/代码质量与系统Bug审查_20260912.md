### SC-15（P1）vol_regime_weighter：约束链现金缓冲破坏，输出权重总和可偏离 1 达 +30%

- **位置**：`utils/alpha/vol_regime_weighter.py:659-733`（`VolRegimeWeighter.enforce_constraints`）
- **问题链**（四步互相放大）：
  1. **步骤 2（现金下限 L692-699）**：现金 < floor 时无条件抬到 floor —— 直接**凭空注入权重**，不做对应压缩；
  2. **步骤 3（差额归现金 L701-708）**：裁剪后总和若 >1，赤字 `delta` **全部塞给现金**——现金可能变负（如 -0.30），且无下限保护；
  3. **步骤 4（负值保护 L710-716）**：现金归零后**不再重新归一**——总和 ≠ 1 直接输出；
  4. **步骤 5（最终校验 L718-726）**：只把 `final_total` 写进日志字符串，**无断言、无告警、无修正**。
- **数值例**（CASH_OFFENSIVE regime，矩阵 ±20%，7 风格各 0.135 + 现金 0.05）：
  - 原始和 = 0.9448 → 抬现金到 floor 后 = 1.3448 → 四个 0.27 风格裁到 0.30 后 ≈ 1.35 → delta = -0.35 → 现金 = 0.05 − 0.35 = **-0.30** → 负值归零；
  - **最终输出**：四个 0.30 + 周期 0.10 + 现金 0 = **总和 1.30（超发 30%）**，现金 = 0（违背 cash_floor=0.05），权益类被从 0.135 抬到 0.30（**+122%**）。全过程零告警。
  - 常规情形（非极端）下同样失真：裁剪产生的赤字不再按比例分摊回风险资产，而是先冲现金——现金被无声挪用，最坏时现金缓冲完全消失。
- **影响**：
  - `etf_option_hedge_rebalancer.py:98,305-313` 真实接入 VolRegimeWeighter（对冲调仓的 regime 适应路径）——启用即踩；
  - `utils/auto_trading_system.py:242,417-460` 走 `USE_VOL_REGIME_WEIGHTER` feature flag，**默认 False**（当前未启用，无实盘影响）——开 flag 前必须先修本条。
- **修复建议**：约束执行改为单次收敛循环——①抬现金时按比例压缩风险风格；②sum>1 的赤字优先从**最高权重风格**扣除（或全风险风格按比例分摊），不得单冲现金；③任何负值归零后必须**重跑整条约束链**；④步骤 5 由日志改为告警+强制修正（fall back 到安全等权+现金 floor）。
- **置信度**：高（代码路径直接推演，多组数值复算一致）。

### SC-16（P3）enhanced_signal_fusion：softmax 无溢出防护 + 上限约束在归一化前  ✅ 已修 (2026-09-12)

- **位置**：`utils/enhanced_signal_fusion.py:535-553`（`_apply_weight_constraints`）
- **问题 ①**：`np.exp([adjusted_scores[s] * 10 ...])` 无 max-shift 减法。`adjusted_scores` 可为负（相关性惩罚相乘），score ≈ -7 时 exp(-70) 无碍，但 score 为大正值时 exp(700) 直接 `OverflowError`/inf → softmax 输出 NaN。异常分数无钳位。
- **问题 ②**：L545-551 先逐源 clip 到 `[min_weight_per_source, max_weight_per_source]`，**然后**才归一化——归一化会把刚压到 0.5 上限的源重新抬超上限（与昨日 portfolio_builder P2-1 同型：约束必须在归一化后仍成立）。极端时单一源可被抬到 ~1.0。
- **消费方现状**：全仓库无生产调用——`signal_fusion.py:1327,1405,1481` 仅注释宣称"由 EnhancedSignalFusionEngine 动态调整"（**实际未接线**，注释与代码不符）；`scripts/_coverage_recalc.py` 为工具脚本。故降级 P3。
- **修复建议**：softmax 加 `exp((s - max(s)) * 10)`；clip 与归一化迭代收敛或裁剪后重分配。**若未来把权重机制真正接线，本条升级为 P1 前置必修**。
- **✅ 修复落地（2026-09-12，PR 见 `cairn/LOG.md` 顶部条目）**：
  - ① 抽出 `_softmax_weights`：max-shift（`exp((s - max) * 10)`，平移不变性）+ 非有限值 `nan_to_num` 清洗 → 溢出/NaN 不可能发生（实测 score=100 与 1e3 均得合法分布）；
  - ② 抽出 `_project_to_capped_simplex`：把权重投影到 `{sum=1, min<=w<=max}`（water-filling，逐轮钉住越界源、余量按基准比例分给未固定源），归一化后约束恒成立（单源主导实测 0.833→0.5）；不可行时 fail-safe 退化等权（不静默放行违规权重）；
  - 终检不变量：非有限值/越界/总和≠1 一律退化等权 + WARNING。
  - **验证**：新增 8 例回归（修复前 **6 failed** → 修复后全绿）；该文件 12→20 passed；相关面 4 文件 **226 passed**；ruff All checks passed。

### 共性根因（第六次同一把尺子）

本批 6 项与前五批沉淀**同族**，并新增两个可复用检查项：

1. **「符号存在性」未纳入任何门禁** —— 幽灵类（SC-32）、幽灵函数（SC-31/SC-34）、幽灵导出（SC-33）
   全部通过所有静态门禁（ruff F821 只查**未定义名**，不查 **import 目标是否存在**）。
   本批新增回归测试用 **AST 反向断言**覆盖该盲区（源码不得再 import 幽灵符号）。
2. **「异常元组缺 ImportError」** —— 依赖缺失属"取不到数据"，但常见异常元组只列数据处理类异常，
   于是依赖缺失**穿透 fail-safe**（SC-31）。凡 `try: from X import Y ... except (<数据类异常>)` 结构，
   必须补 `ImportError`。
3. **「回退候选与解析口径不匹配」**（SC-29/SC-30）—— 同一模块"能读到的文件"与"期望的结构"不一致，
   而失败被默认值兜成**语义相反的结论**（无排期 → 已完成）。
4. 与前五批（伪审计来源串 / 物理量级无护栏 / 静态数字冒充运行时值 / 同一兜底值兼作分子分母 / NaN 比较恒 False）
   同属 **"缺数据 ≠ 通过"** 铁律的失败路径变体。
