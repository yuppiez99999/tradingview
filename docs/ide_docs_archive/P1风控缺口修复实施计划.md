# P1 风控缺口修复实施计划 (v8.6.5 → v8.6.6)

## Context

第二轮 CRO 黑天鹅防御审计（2026-07-26）修复了 3 个 P0 级致命 bug（P0-D/E/F），评分从 3.5 提升至 7.5。但审计同时揭示 6 个 P1 级风险缺口（broker_callback 作用域 bug / 大盘熔断缺失 / 隔夜跳空缺失 / 全局撤单缺失 / 相关性对冲孤立 / shadow_account risk_managed 未集成生产），导致系统在黑天鹅极端场景下仍有 4 项能力空白：

- L3 紧急协议因变量作用域 bug 实际无法触发真实动作
- 沪深300 跌 5%/7% 场景无任何响应
- 隔夜外盘大跌无 09:25 前仓位调整
- 全市场涨跌停 > 2000 家无全局撤单
- CorrelationHedger 模块已实现但未接入 EOD Guard 链
- shadow_account 验证过的 risk_managed 算法未移植到生产 PortfolioOptimizer

本次修复目标：闭合全部 6 项 P1 缺口，将 EOD Guard 链从 5 个 Guard 扩展为 7 个 Guard，覆盖大盘级 / 组合级 / 对冲级三层风控，CRO 评分目标从 7.5 提升至 9.0+。

## 修复优先级与依赖关系

```
第一批（并行）: P1-G (15min) + P1-L (4h)     — 无依赖
第二批:         P1-K (2h)                      — 依赖 P1-G
第三批:         P1-H (4h)                      — 依赖 P1-G
第四批（并行）: P1-J (3h) + P1-I (3h)          — 依赖 P1-H
```

关键路径：P1-G → P1-K → P1-H → P1-J，总工时约 16 小时。

## 实施步骤

### 步骤 1：P1-G — broker_callback 变量作用域 bug 修复（15 分钟）

**文件**：[v8.3_institutional/daily_workflow.py](file:///e:/各种PY程序/28-终极量化交易系统8.4/v8.3_institutional/daily_workflow.py)

**修改点**：L2547 单行修改

```python
# 修复前 (BUG):
ks = KillSwitch()

# 修复后 (P1-G FIX):
ks = self.ks  # 复用已注册 broker_callback 的主实例 (P1-G 修复)
```

**原理**：L7246-7249 已在 `self.ks` 上注册 `self._execute_kill_switch_callback`，但 L2547 创建了未注册 callback 的局部 `ks`，导致 L2568 `ks.execute_kill_switch(3)` 抛 RuntimeError 被 L2570 吞掉，L3 紧急协议完全失效。复用 `self.ks` 后，L3 触发将真实调用 callback 执行（标记 halt_all_trading + 变现红利 ETF）。

**实盘影响**：`_execute_kill_switch_callback` 中 L2/L3 动作状态为 `"logged" if self.dry_run else "pending_broker_api"`，dry_run=True（默认）仅记录日志不下单，不影响 500 万实盘。

### 步骤 2：P1-L — shadow_account risk_managed 算法移植（4 小时）

**文件**：[utils/portfolio_optimizer.py](file:///e:/各种PY程序/28-终极量化交易系统8.4/utils/portfolio_optimizer.py)

**新增方法**：`apply_risk_management(target_weights, daily_pnl_history, config=None) -> Tuple[Dict, Dict]`

**算法移植自**：[research/vibe_trading_factor_analysis/shadow/shadow_account.py](file:///e:/各种PY程序/28-终极量化交易系统8.4/research/vibe_trading_factor_analysis/shadow/shadow_account.py) L353-L446 `_apply_risk_management`

**关键算法**：

```python
# 默认参数（与 shadow_account.RISK_MANAGED_* 常量对齐）
TARGET_VOL = 0.15          # 目标年化波动率 15%
VOL_LOOKBACK = 20          # 波动率回看窗口 20 日
DD_DERISK_THRESHOLD = 0.05 # 回撤 > 5% 触发去杠杆
DD_DERISK_FACTOR = 0.5     # 去杠杆至 50% 敞口
SCALER_CAP = 2.0           # 缩放因子上限
TRADING_DAYS_PER_YEAR = 252

# 1. 波动率缩放
recent = daily_pnl_history[-vol_lookback:]
realized_vol_annual = np.std(recent, ddof=1) * sqrt(252)
vol_scaler = min(target_vol / realized_vol_annual, scaler_cap)

# 2. 回撤去杠杆（基于昨日净值避免前视偏差）
current_dd = (peak - current_value) / peak
dd_scaler = dd_derisk_factor if current_dd > dd_derisk_threshold else 1.0

# 3. 合并并应用
combined_scaler = vol_scaler * dd_scaler
scaled_weights = {sym: w * combined_scaler for sym, w in target_weights.items()}
```

**影响隔离**：
- 新增独立方法，不修改 `adjust_target_weights()` 现有签名
- 调用方需主动调用，默认不启用
- `daily_workflow.py::phase_execute`（实盘执行）**不调用**此方法
- 仅 `launch_shadow_account.py` / 影子账户监控等研究层调用方启用

**依赖**：需新增 `import numpy as np`（现有仅 `import math`）

## 风险控制策略

### 1. 新增 Guard 失败时降级
- 每个 Guard 独立 try-except（遵循现有 `run_all_guards()` L644-678 模式）
- 风控类 Guard 崩溃时强制 `spot_build_allowed=False`（fail-closed）
- 对冲类 Guard 崩溃时仅记录错误，不阻断主流程

### 2. 数据源不可用时 fallback
| 模块 | Layer 1 | Layer 2 | Layer 3 (fail-closed) |
|------|---------|---------|------------------------|
| market_circuit_breaker | astock_realtime | akshare | 返回 -8% 触发 L3 |
| overnight_gap_monitor | ExternalDataSource | 本地缓存 | 返回 -4% 触发 L3 |
| liquidity_crisis | akshare 全市场 | astock_realtime 样本 | 返回 2500 触发撤单 |
| correlation_hedger | daily_pnl_report 历史 | - | 返回 NO_HEDGE |

### 3. 500 万实盘影响隔离
- **P1-L**：新增独立方法，默认不启用，仅影子账户调用
- **P1-G**：`_execute_kill_switch_callback` 中 `dry_run=True` 仅记录日志不下单
- **P1-H/J/I**：Guard 清空 `plan['execution_plan']` = 次日不交易（保守保护），不会错误下单
