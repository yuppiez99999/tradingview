## 2. 近期任务（观察期内, 现在 ~ 2026-08-10）

**核心约束**: 不修改 V9 基线, 不写入生产路径, 只做准备工作

### T1: 评估器增强 — 集成完整反作弊检测

**优先级**: 高
**预估**: 1-2 天
**目标**: 将简化版 PIT 和 Walk-Forward 替换为 v8.3 完整实现

**子任务**:
- T1.1: 集成 `PITChecker` (6 维度未来函数检测)
  - 修改 `strategy_evaluator.py` 的 `_check_pit_violations()` 方法
  - 当前仅检查时间戳单调性 → 完整 6 维度检查
  - 输入: signal_history (含 timestamps, features, train_test_split)
- T1.2: 集成 `PurgedWalkForward` (时序安全 CV)
  - 修改 `_compute_wf_sharpe_decay()` 方法
  - 当前仅前后半段对比 → Purged K-Fold (默认 5 折, purge=5, embargo=5)
  - 样本不足时降级为当前简化版
- T1.3: 集成 `ParameterSensitivity` (参数稳定性)
  - 新增 `_score_param_stability()` 方法
  - 如果 signal_history 含 params 字段, 计算局部敏感性
- T1.4: 更新验证脚本, 覆盖新增的反作弊检测

**验收标准**:
- PIT 违规检测: 构造含未来函数的 signal_history, 检测到 ≥1 个违规
- Walk-Forward: 252 条数据, 5 折 CV, 返回衰减率
- 不破坏现有 7 项测试

**文件变更**:
- `utils/alpha/strategy_evaluator.py` (修改)
- `scripts/_verify_strategy_evaluator.py` (修改)

### T3: EvolutionOrchestrator 原型 (只读模式)

**优先级**: 中
**预估**: 2-3 天
**目标**: 搭建外层循环编排器骨架, 只读模式, 不触发任何进化动作

**子任务**:
- T3.1: 创建 `utils/alpha/evolution_orchestrator.py`
  - Feature Flag: `USE_EVOLUTION_ORCHESTRATOR` (默认 False)
  - 核心方法:
    - `collect_metrics()`: 从 daily_returns.jsonl 读取 (只读)
    - `evaluate_current()`: 调用 StrategyEvaluator
    - `log_decision()`: 记录决策到 `reports/evolution/decisions.jsonl`
    - `get_status()`: 返回编排器状态
  - 不调用: DriftMonitor, ABTestFramework, AutoRetrainScheduler (观察期内禁用)
- T3.2: 决策日志格式设计
  ```json
  {
    "timestamp": "ISO8601",
    "action": "evaluate_only",
    "public_score": 0.30,
    "private_score": 0.32,
    "reward_hacking_risk": 0.40,
    "recommendation": "continue",
    "sample_count": 2,
    "observation_day": 1,
    "reason": "..."
  }
  ```
- T3.3: 编写验证脚本
  - 测试只读模式: 不修改任何生产文件
  - 测试决策日志: 正确写入 JSONL
  - 测试 Feature Flag 关闭时降级

**验收标准**:
- 编排器只读, 不触发任何进化动作
- 决策日志正确持久化
- Feature Flag 关闭时返回降级状态
- 不修改 V9 基线 (HC-4 兼容)

## 3. 中期任务（观察期后, 2026-08-10 ~ 2026-08-30）

**前提**: Stage 2 评估通过, 可修改 V9 基线
**策略**: 渐进推进 (用户确认)

### M1: 启用 MLOpsPipeline 监控模式 (第 1 周)

**策略**: 仅告警, 不自动重训

- 启用 `USE_MLOPS_PIPELINE=True`
- 启用 `USE_DRIFT_DETECTOR=True`
- 保持 `USE_AUTO_RETRAIN=False` (手动触发)
- 验证: DriftMonitor 4 维度检测正常, 告警持久化

### M2: 评估器接入 ABTestFramework (第 2 周)

- 修改 StrategyEvaluator, 新增 `to_ab_test_config()` 方法
- 当 recommendation == "promote" 时, 自动创建 A/B 测试
- 验证: A/B 测试全流程 (创建 → 记录 → 评估 → promote/rollback)

### M3: 启用自动重训 (第 3 周)

- 启用 `USE_AUTO_RETRAIN=True`
- 验证: DriftMonitor 触发 → AutoRetrainScheduler 执行 → 模型注册 → A/B 测试
- 安全护栏: 重训失败不阻塞主路径, 降级为旧模型

### M4: EvolutionOrchestrator 启用 (第 3 周末)

- 启用 `USE_EVOLUTION_ORCHESTRATOR=True`
- 集成: Evaluator + DriftMonitor + ABTestFramework + ModelRegistry
- 验证: 完整外层循环 (评估 → 决策 → A/B → 晋升/回滚)

## 4. 远期任务（2026-09 ~ 2026-10）

### R1: LLM 策略 Ideation 模块

- `utils/alpha/strategy_ideation.py`
- LLM 生成策略改进假设
- 输入: performance_report + 失败案例
- 输出: StrategyHypothesis 列表

### R2: 假设验证框架

- `utils/alpha/hypothesis_tester.py`
- 对 LLM 生成的假设进行 A/B 测试
- 统计显著性检验 + 效应量

### R3: 知识沉淀库

- `reports/evolution/knowledge_base.jsonl`
- 记录: 成功/失败的策略改进
- 反馈给 LLM, 避免重复犯错

### R4: 完整双层闭环

- 外层循环自动化: 每周触发一次
- 内层循环: Shadow → 灰度 → 全量
- 安全护栏: 累计改进 > 20% 触发人工审核
