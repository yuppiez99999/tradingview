# 配置漂移修复与期权保护接通

## Context

本周建仓执行率仅 4.1%(实际注资 ¥32,621 vs 计划 ¥800,000)。用户四层归因分析指向配置漂移,经代码核查确认真实根因比单一参数漂移更复杂:

1. **trade_plan 文件 stale**:`trade_plan_2026072X.json` 于 7/22 生成,记录 `daily_capital=150,000`、`day_capital=100,000`、strategy="每日15万",但代码 PHASES 已更新为 `daily_capital=200,000`、strategy="每日20万"——文件从未用新代码重新生成。
2. **day_capital 计算 bug**:[generate_daily_trade_plan.py:649](file:///e:/各种PY程序/28-终极量化交易系统8.4/v8.3_institutional/generate_daily_trade_plan.py#L649) 用 `phase_capital/duration_days`(=10万)而非 `daily_capital`(=20万),两个字段在同一段输出里打架,执行器读的是 `day_capital`。
3. **保护性 Put 零执行**:`ProtectivePutEngine.generate_put_orders()` 接口存在且配置齐全(上证50 Put 60张/90万预算),但 `_load_hedge_fund_overlays()` 只调用了 Theta(Covered Call)和 Gamma,从未调用 ProtectivePutEngine——Put 订单根本没被生成,不是执行失败。

用户决策:建仓周期保持 8/21(代码现状);Put 部署采用"生成执行单+MOCK_BROKER 模拟撮合"(符合硬约束)。

### 改动 2:接通 ProtectivePutEngine

**文件**:[v8.3_institutional/generate_daily_trade_plan.py](file:///e:/各种PY程序/28-终极量化交易系统8.4/v8.3_institutional/generate_daily_trade_plan.py)

**新增逻辑**(复用 [utils/protective_put_engine.py](file:///e:/各种PY程序/28-终极量化交易系统8.4/utils/protective_put_engine.py) 的 `ProtectivePutEngine`):

```python
# === 2.5 ProtectivePut 引擎 — 尾部保护 Put 部署 ===
try:
    from utils.protective_put_engine import ProtectivePutEngine
    ppe = ProtectivePutEngine()
    put_result = ppe.generate_put_orders()
    put_orders = put_result.get("orders", []) if isinstance(put_result, dict) else []
    if put_orders:
        # 转换为与 Theta options_orders 一致的格式
        for po in put_orders:
            po.setdefault("order_type", "LIMIT")
            po.setdefault("session", "morning")
            po.setdefault("direction", "BUY_PUT")
        overlays.setdefault("options_orders", []).extend(put_orders)
        overlays["protective_put"] = {
            "available": True,
            "deployed": True,
            "orders_count": len(put_orders),
            "total_budget": sum(po.get("est_premium_total", 0) for po in put_orders),
            "targets": [po.get("underlying", po.get("code")) for po in put_orders],
        }
    else:
        overlays["protective_put"] = {
            "available": True, "deployed": False,
            "reason": put_result.get("reason", "无需部署") if isinstance(put_result, dict) else "无订单",
        }
except Exception as e:
    overlays["protective_put"] = {"available": False, "error": str(e), "deployed": False}
```

**注意**:`generate_put_orders()` 的实际返回结构需在执行时读取 [utils/protective_put_engine.py:233-270](file:///e:/各种PY程序/28-终极量化交易系统8.4/utils/protective_put_engine.py#L233) 确认字段名,按实际返回适配订单转换逻辑。

## 风险与约束

1. **MOCK_BROKER 限制**:Put 订单生成后由 MockBroker 模拟撮合,不真实下单。符合项目硬约束"System must continue using simulated trading environment"。
2. **ProtectivePutEngine 接口适配**:`generate_put_orders()` 返回结构需在执行时确认,计划中的字段映射可能需要微调。
3. **8/21 周期不变**:用户确认保持代码现状的 8/21 完成日,不缩短到 8月初。`duration_days=30` 不变,`daily_capital=200,000` 不变。
4. **day_capital 语义**:修复后 `day_capital == daily_capital == 200,000`。若执行器有独立的 `day_capital_multiplier` 缩放(见 [auto_v76_runner.py:270](file:///e:/各种PY程序/28-终极量化交易系统8.4/v8.3_institutional/auto_v76_runner.py#L270)),实际执行量仍可能低于 20万——这是执行层风控,不在本次修复范围。
