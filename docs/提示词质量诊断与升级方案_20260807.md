## 逐文件诊断

### 1. `ai/recommendation_generator.py` — 盘后 AI 建议生成

**当前状态**: 已按 v1.0 质量规范实现双层防御 ✅

**诊断**:
- ✅ 6 要素设计规范齐全（身份/任务/反描述化/关键词/格式/质量）
- ✅ 智能截断：操作建议优先 + 描述行过滤
- ✅ 质量日志可观测
- ⚠️ **关键词硬编码分散**：Prompt 和解析器各维护一份关键词列表，未统一
- ⚠️ **数据注入粗糙**：JSON dump 所有数据，无优先级/摘要化，大持仓时可能超 token
- ⚠️ **无 few-shot 示例**：LLM 在没有示例时输出不稳定
- ⚠️ **无约束条件**: 未注入风控规则（单标的 10%/行业 30%）。
- ⚠️ **温度 0.4 偏高**：对于需要精确格式的场景，建议 0.1-0.2

**升级建议**:
1. 添加 2 条 few-shot 示例固化输出格式
2. 注入风控约束（max_single=10%, sector=25%, VaR95=1.5%）
3. 数据注入改为摘要化（只送 Top5 盈亏 + Top3 对冲 + 关键指标）
4. 降温度到 0.2
5. 统一关键词清单为独立常量

### 2. `ai_decision/debate_engine.py` — Bull/Bear/Judge 辩论

**当前状态**: 简洁角色化提示词，基本可用但**严重欠缺结构化** 🟡

**诊断**:
- 🔴 **无结构化输出约束**: Bull/Bear 输出纯文本，无 JSON 字段约束，`_parse_strength_conf` 被迫用关键词计数回退解析（不可靠）
- 🔴 **无事实引用强制**: "基于给定事实底座" 但没有要求引用具体数据点
- 🔴 **无量化标准**: "强度(1-10)" 实际没有被解析使用（`_parse_strength_conf` 靠关键词数推断）
- 🟡 **无反驳模板**: 次轮反驳 prompt 过于简单，"最强反驳" 没有结构指引
- 🟡 **Judge 裁决标准模糊**: "比较证据直接性/可验证性/时间敏感度" 没有定义权重
- 🟡 **无争议检测**: 若 Bull/Bear 方向一致（非辩论场景），仍走完整流程浪费 token
- 🟢 **多空隔离好**: Bull 见 Bear 观点反驳、Bear 见 Bull 观点反驳 ✓

**升级建议**:
1. 输出强制 JSON 约束：`{bullish_strength, key_evidence, key_catalyst, weakest_assumption, confidence}`
2. 事实引用强制格式：`[来源:数据点]` 格式要求
3. Judge 增加裁决矩阵模板
4. 增加"无需辩论"快速路径（方向一致 + 置信度 > 0.7 → 直接聚合）
5. 次轮反驳增加结构化对比模板

### 3. `utils/glm5_decision_engine.py` — 五场景系统提示词 + 用户提示词

**当前状态**: 最核心的提示词文件，问题最多 🔴

**诊断**:

| 场景 | 问题 |
|------|------|
| **intraday_decision** | 🔴 角色定义过于宽泛（20年经验但无具体操作框架）；决策原则是通用风控常识未融入系统实际约束（VaR95=1.5%、对冲100万独立）；输出格式要求 Markdown 表格但无示例行 |
| **rebalancing_analysis** | 🔴 分析框架过于学术（康波周期/十五五规划/社保基金风格），实际系统已有具体约束但未注入；止损线 -10%/+20% 与系统实际 -8% 不一致 |
| **macro_analysis** | 🟡 分析维度偏重长期叙事，缺少可执行的短期量化指标 |
| **report_generation** | 🟡 `{report_type}` 占位符无类型枚举，可能导致幻觉 |
| **light_analysis** | 🟢 简洁可用，但无输出格式约束 |
| **user prompt** (`_build_decision_prompt`) | 🔴 仅 JSON dump 数据 + 模板化要求；512+ 行决策要求但无 few-shot；表格格式要求过于复杂（10列）；无 token 预算管理 |

**升级建议**:
1. 每个场景 system_prompt 注入系统实际约束（VaR95=1.5%、单标10%、板块25%、期货100万独立）
2. intraday 增加"30秒决策模板"（极简输出）
3. rebalancing 对齐真实风控参数（-8%止损而非 -10%）
4. user prompt 添加 1 条 few-shot 示例
5. user prompt 精简表格为 7 列（去掉冗余字段）
6. 增加 token 预算意识（max 1200 tokens for intraday）
7. 统一 confidence 定义为"模型对判断的确信度"防止模糊

## 通用升级原则

1. **结构化输出优先**: 所有关键决策提示词强制 JSON 输出
2. **约束注入**: 系统实际风控参数（VaR95=1.5%、单标10%、板块25%）注入每个相关提示词
3. **Few-shot 先行**: 至少 1 条示例固化格式预期
4. **温度对齐**: 格式敏感场景 0.1-0.2，创意场景 0.3-0.5
5. **Token 预算**: 每个提示词标注预期 max_tokens，防止超长输出
6. **关键词统一**: 单一来源 `config/llm_keywords.yaml`
7. **可观测性**: 每个 LLM 调用点输出质量统计日志
